## «Автовывоз» при открытии

Активные рейсы идут по возрастанию номера строки. При открытии последняя строка центрируется в видимой области данных. Пример для браузерной сверки — `/vitrine?table=vyvoz`. Подробности в [контракте Витрины](../app/local-admin/VITRINE.md).

На изолированном стенде с синтетическими данными в Chrome проверены открытие после входа и по прямой ссылке, центрирование при высоте окна 900 и 1200 пикселей, фокус первой видимой ячейки, Ctrl+Home и Ctrl+End, граница в 6 000 активных рейсов, архив, одна строка и пустая таблица.

Под последним рейсом доступны десять пустых строк ввода. На изолированном стенде в Chrome проверены переход вниз с клавиатуры, создание рейса из ячейки, переход фокуса на сохранённую строку и восстановление десяти пустых строк. Повтор запроса вернул тот же рейс, журнал записал создание и правку по одному разу. В архиве строки ввода скрыты, в справочнике статусов рейса остались три строки ввода.

## Пакетное заполнение учётных записей

Справочник принимает короткий логин или email до 60 символов. При сохранении логин приводится к нижнему регистру. Учётные записи с ролями «Аналитика», «Админ» и «Суперадмин» видны в справочнике, списке API и журнале управления сотрудниками только суперадмину. Он же может их редактировать и назначать эти роли. Права этих пользователей в рабочих разделах определяются общей политикой доступа.

`php tools/provision_employee_roster.php <имя_схемы> <логин_суперадмина>` читает JSON-массив через stdin. У строки обязательны `login`, `role` и `password`. Поля `name`, `email` и `previousLogin` опциональны. Приоритет у точного логина. `previousLogin` позволяет переименовать существующую запись с сохранением ID. Отсутствующий `name` берётся из существующей записи или из названия системной роли. Для нового email-логина то же значение по умолчанию записывается в Email.

Поддерживаются системные коды `manager`, `logist`, `dispatcher`, `admin`, `superadmin` и дополнительные `directory_senior_manager`, `directory_senior_logist`, `directory_analytics`. Дополнительные роли создаются при первом использовании. Скрипт сохраняет пакет одной транзакцией, пишет аудит и пропускает записи, уже совпадающие по профилю, роли и паролю. Перед запуском сохраните приватную резервную копию. На целевом стенде запустите скрипт отдельно после выкладки кода. Передавайте список в приватном окружении через stdin. Шестизначный начальный пароль принимается при закрытом пакетном переносе. Для формы сохраняется минимум 8 символов.

Проверено на отдельном MySQL/PHP с синтетическими данными. Вход, права в сетке и API, фильтрация аудита, повторный импорт и откат при ошибке проходят.

На стенде суперадминистратор также может выполнить одноразовый перенос через `POST /api/workspace/employee-roster` с CSRF и приватным массивом `employees`. При совпадающем логине проверяются активность и роль, затем действующая запись полностью сохраняется. Переименование через этот маршрут запрещено. Все новые записи, роли, аудит и квитанция записываются одной транзакцией. Повторный запрос получает `409`. Перенос через кабинет выполняется отдельно после выкладки.
