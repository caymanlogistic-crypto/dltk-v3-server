# Проверка быстродействия серверного стенда

Скрипт `tools/benchmark.py` запускает ограниченный одновременный сценарий для 15 сотрудников. Он читает бизнес-данные, не меняет ячейки, пользователей, справочники или настройки. Вход создаёт обычные сессии и служебные записи защиты входа; необязательная проверка WebSocket создаёт краткоживущие tickets.

```sh
python3 tools/benchmark.py \
  --base-url https://SERVER:8443 \
  --workers 15 \
  --password-file /path/outside/repository/demo-access.txt \
  --websocket \
  --output artifacts/server-benchmark.json
```

Пароль не передаётся аргументом командной строки и не попадает в отчёт. Файл может содержать одну строку пароля либо существующую строку `Пароль для демоаккаунтов:` из `demo-access.txt`. Альтернатива — переменная окружения `DLTK_BENCH_PASSWORD`, заполненная через штатный закрытый механизм. Файл/значение не коммитить. Серверные демоаккаунты должны иметь общий пароль для этого сценария.

Скрипт использует `manager`, `logist`, `dispatcher`, `head`, `admin`, `superadmin` по кругу, но у каждого из 15 клиентов собственная cookie-сессия. Это 15 сеансов, а не 15 отдельных учётных записей.

Измерения разделены:

1. Настройка авторизации, отдельно от чтения таблицы.
2. Первая страница «Вывоза»: время получения заголовков и полного тела, сетевой размер и размер после распаковки gzip.
3. Короткий запрос bootstrap.
4. Порция следующих 100 строк. Если строк меньше, размер порции отражается в отчёте; пустая выборка явно пропускается.
5. По `--websocket`: одновременные авторизованные подключения до `ready`, затем удержание всех соединений две секунды. Изменения бизнес-данных через WS не отправляются.

Для HTTP выводятся p50/p95 и диапазон, p95 — ближайший ранг. Время до заголовков — приближение TTFB, не захват сетевых пакетов. Полное время — получение тела без локальной распаковки и JSON-разбора. Размер wire-body не включает HTTP/TLS-заголовки. urllib использует HTTP/1.1; это не эмуляция браузерного HTTP/2. По умолчанию одна серия; `--rounds` допускает 1–5, `--workers` 1–30. Таймаут сетевого запроса — 30 секунд.

Для локального smoke-теста:

```powershell
python tools/benchmark.py --base-url http://127.0.0.1:33385 --workers 3 --password-file PRIVATE/demo-access.txt --websocket --output artifacts/local-benchmark.json
```

Loopback идёт напрямую, внешние адреса учитывают прокси среды. `--no-proxy` принудительно выбирает прямое соединение. В отчёт попадает только режим прокси, не его адрес или credentials. TLS-проверка обязательна: небезопасного флага нет. HTTP-перенаправления на другой origin и WS-перенаправление на другой hostname не разрешаются.

Отчёт не содержит содержимого ячеек, имён заказчиков, IDs строк, cookies, tickets или пароля. Он не измеряет FPS/paint, задержку обработки мыши, доставку изменённой ячейки, длительную стабильность или восстановление после сбоя. Эти проверки остаются отдельными. Короткий успешный прогон не означает готовность production или выполнение SLA; результаты сравнивать при одинаковых сетевых условиях, числе клиентов и составе данных.

Для WebSocket требуется установленная серверная зависимость `websockets==15.0.1`; HTTP-сценарии используют стандартную библиотеку Python.
