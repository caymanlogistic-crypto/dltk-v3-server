# Локальный запуск и проверки

## Обычный Windows-стенд

В исходной папке «ЛК-ДЛТК V3» штатный запуск выполняется из корня.

```powershell
powershell -NoProfile -File tools/start_workspace.ps1
curl.exe --noproxy '*' -fsS http://127.0.0.1:33385/login -o NUL
```

Приложение открывается по [адресу входа](http://127.0.0.1:33385/login). В составе запуска MySQL `127.0.0.1:33384` с рабочей схемой `dltk_v3_workspace`, PHP `33385` и Python WS `33386`. Профиль и доступ к демоучёткам хранятся в приватном каталоге экземпляра MySQL. Существующий автозапуск и установленная среда описаны в `project-hub/LOCAL_SYSTEM_HANDOFF.md` исходной папки. Запуск предназначен для этого единственного стенда. Для проверки кандидата используйте его worktree.

## Worktree для задачи

В существующем клоне серверного репозитория выполните команды, подставив имя задачи. Здесь команды предназначены для PowerShell.

```powershell
git fetch origin main
$dltkTask = 'task-short-name'
git worktree add -b "codex/$dltkTask" "../dltk-v3-$dltkTask" origin/main
Set-Location "../dltk-v3-$dltkTask"
```

Проверьте, что `git status --short --branch` и корень `git rev-parse --show-toplevel` указывают на рабочую ветку и её папку. На следующих шагах команды выполняются из её корня.

## Быстрый набор без базы

PHP CLI требует `mbstring`. интеграционная проверка также требует `pdo_mysql`. Node.js используется для проверки JavaScript. Python-зависимости перечислены в [requirements.txt](../requirements.txt).

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
php tests/vitrine_clipboard_check.php
php tests/runtime_config_check.php
.\.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_server_*.py'
```

При изменении PHP/JS запустите `php -l <файл>` и `node --check <файл>` для изменённых файлов. Полный набор синтаксических и регрессионных проверок указан в [GitHub Actions](../.github/workflows/check.yml). Он выполняется с проверочной конфигурацией и без рабочей БД. Для проверки рабочей ветки используйте `gh workflow run check.yml --ref codex/task-short-name` со своим именем ветки. Для этого запуска GitHub пропускает deploy.

## Изолированный HTTP, WebSocket и браузер

На Windows используйте MySQL 8.4 и PHP CLI в PATH или передайте полные пути через `--mysqld` и `--php`. Скопируйте в команду фактический путь к `tools/workspace_setup.py` из исходной папки. Этот файл используется только как источник схемы и кодов ролей.

```powershell
.\.venv\Scripts\python.exe tests/run_isolated_workspace.py --schema-source '..\ЛК-ДЛТК V3\tools\workspace_setup.py'
```

Скрипт поднимает новый локальный экземпляр MySQL, отдельные PHP и WS на свободных loopback-портах. Конфигурация и сессии находятся во временной папке запуска. Синтетические записи и тестовые аккаунты создаются с нуля, источник данных из рабочего стенда не подключается. E2E проверяет вход двух аккаунтов, присутствие, правку демоячейки, сообщение другому пользователю, точный аудит и восстановление значения. Приложение и временная база останавливаются при выходе.

Для браузера добавьте `--serve`. Из вывода возьмите URL и путь к временному файлу демодоступа, откройте страницу и проверьте конкретную правку. Завершите процесс после проверки. Для параллельных запусков у каждого worktree будут свои порты и приватная папка. Для большого manifest и нагрузочных проверок нужны данные соответствующего масштаба, текущий синтетический набор мал.

Опциональный `tests/server_e2e.py` умеет работать с внешним стендом и пишет одну подтверждённую демоячейку с последующим восстановлением. После выкладки используйте его только для задачи, которой требуется согласованная проверка записи. Для основного smoke достаточны [read-only проверки](AUTODEPLOY.md#цикл-агента) и чтение страницы по сценарию задачи.
