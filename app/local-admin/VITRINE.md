# Server copy of DLTK V3 vitrine

PHP-FPM public root: app/local-admin/public. Requests route through public/index.php; Nginx serves assets directly. Only the working DB is used. Runtime config is in a private [workspace] INI file selected by DLTK_CONFIG_FILE. Keep config/runtime.ini, data exports, passwords and backups out of Git. UI components/styles and current keyboard/editing/live-presence behavior are preserved from the local project.

Runtime contract: [workspace] INI, APP_URL/WS_URL/DB_HOST/DB_PORT/DB_NAME/DB_USER/DB_PASSWORD/PRIVATE_DIR. DLTK_CONFIG_FILE selects the private file. APP_URL is a root origin (a separate virtual host/port), not a subdirectory. Preserve the incoming Host header at Nginx. Cookie name is dltk_v3_server and Secure is enabled for HTTPS APP_URL. /api/health returns dltk-v3-server-v1 and checks only the working DB. Unknown legacy source/admin routes return404.

Portable QA: all PHP and JavaScript syntax checks,66 format checks and9 HTTP integration checks passed locally using a dedicated temporary server process. The latter exercised health, distinct cookie, account login,6000-row grid,5 tables/6 roles, configured WebSocket URL, Host/Origin rejection and removed legacy route. No business values were written. Actual Linux deployment/performance remain separate acceptance steps.

## Стандарт интерфейса и согласование

[«Автовывоз»](http://127.0.0.1:33485/vitrine?table=vyvoz), [вход](http://127.0.0.1:33485/login) и [справочник терминалов](http://127.0.0.1:33485/vitrine?catalog=entries&id=12) показывают действующий стандарт ЛК ДЛТК. Вход, таблицы, справочники и служебные страницы подключают один файл `public/assets/vitrine.css`. Разметка и поведение берутся из общих компонентов приложения. JavaScript передаёт предусмотренные значения CSS-переменных, например ширину столбца и цвет активного пресета. Цветовые группы, значения палитр и выбор пресета хранятся отдельно от правил оформления.

Добавление компонента, изменение согласованного внешнего вида, разметки, подписей, состояний, клавиатурного поведения или локальное исключение требуют явного согласования с владельцем до реализации. Согласие на доработку функции само по себе не разрешает менять дизайн. Агент фиксирует согласование в карточке и PR. После согласования правка вносится в общий компонент и распространяется на все места его использования. Для выпадающего календаря сначала утверждается один образец со светлой и ночной темами, клавиатурой и состояниями. После утверждения все формы с календарём используют этот компонент.

Дополнительные CSS-файлы, встроенные правила и генерация CSS из JavaScript запрещены. Проверка `tests/test_server_style_contract.py` сверяет подключение единственного CSS и контрольную сумму. Изменение контрольной суммы, правил проверки или обход проверки разрешены только по прямому согласованию владельца.

## Системное и личное отображение

Во всех таблицах и справочниках используются одни и те же действия для ширины, перестановки, закрепления и скрытия столбцов. Настройки суперадминистратора задают системное отображение для конкретной таблицы или справочника, включая контраст линий и ширину блока. Цветовой пресет суперадминистратора является общим для приложения. Личный выбор имеет приоритет по каждому параметру, а для ширины — отдельно по каждому столбцу. Остальные параметры продолжают наследоваться. «Сбросить ширину» у пользователя восстанавливает системные значения, у суперадминистратора — исходные ширины столбцов.

Локальная сверка в Edge охватила вход, «Автовывоз», справочник терминалов и журнал. На изолированной базе проверены два пользователя с разными настройками, обновление системных значений в открытой вкладке, сброс личной ширины, порядок с клавиатуры, анимация, закрепление и подтверждение скрытия в справочнике. Проверка стилей запускается в GitHub Actions для PR в main.

## Подсказки при наведении

Интерфейс приложения не показывает всплывающие подсказки при наведении. Это правило действует для таблиц, справочников, диалогов и элементов управления. Для доступных имён элементов применяются видимые подписи и ARIA. Уведомления по действиям пользователя выводит PlanexNotifications.

В Edge проверены вход, «Автовывоз», справочник клиентов и журнал. Имитация обновления ячейки подтвердила, что подсказка не возвращается.

Во всех таблицах и справочниках один щелчок выделяет ячейку и переводит на неё фокус. Двойной щелчок, Enter или F2 открывают редактор или карточку ячейки. Это же правило применяется к редактируемым значениям внутри списков менеджеров и точек выгрузки. Кнопки, ссылки и пункты внутри открытого редактора активируются одним щелчком. Если поле поддерживает ввод первым символом, этот способ тоже доступен.

Независимая проверка во встроенном браузере на порту 33615 охватила «Слот», «Время», обычные и пустые ячейки, связанные поля, справочник клиентов и вложенные списки. Проверены фокус с клавиатуры, сохранение черновика при попытке открыть другую ячейку, кнопка карточки водителя и меню строки.

## Страница входа

После успешной авторизации экран входа с индикатором остаётся видимым до первой отрисовки «Автовывоза». Первый ответ содержит строки для видимой части экрана, а оформление и настройки столбцов применяются до отрисовки. Между страницами выполняется плавное затухание за 200 мс. При системном уменьшении движения переход выполняется без анимации. В Edge проверены обычная и замедленная загрузка, высокий экран и режим уменьшенного движения.

Страница входа использует верхнюю панель Витрины, шрифт IBM Plex Sans и общие компоненты формы, полей и кнопок. Оформление учитывает последний цветовой пресет браузера. При отправке на кнопке «Войти» появляется индикатор ожидания. Повторные клики и Enter не отправляют новый запрос. После ошибки кнопка снова доступна, сообщение выводится сверху через PlanexNotifications.

Пример для сверки — маршрут /login. В изолированной серверной копии браузерная проверка подтвердила расположение элементов, шрифт, обязательное поле пароля и уведомление при неверном входе по Enter.

Проверка во встроенном браузере: выбор и повторное открытие пресета, возврат к базовому, таблица, условные заливки, редактор, справочник, журнал и страница входа. ## Клиент и менеджер в «Вывозе»

Для включения сценария справочник с `kind='clients'` привязывается к полю B таблицы `vyvoz`. После перехода на учётные записи назначение хранит ID пользователя и позицию в `client_account_manager_links`. AL использует те же имена, что и B справочника «Клиенты». До перехода читаются прежние связи с профилями или архивные значения `catalog_managers_<id справочника>`. Список использует общий `VitrineSelect`.

Выбранный клиент и вычисленное AL сохраняются в одной транзакции. При чтении AL подставляется из справочника, в том числе для старых строк. Исторические данные при чтении сохраняются. Если клиент или менеджер не указан, значение AL пустое и отображается прочерк. Для AL пишутся отдельные версия, аудит и событие. Ответ сохранения возвращает обновлённую ячейку AL клиенту, который инициировал операцию.

У столбца значок связи с подписью «Из справочника клиентов» при наведении и фокусе. Светлый фон отмечает происхождение значения. AL можно выделять и копировать. Enter и F2 объясняют источник через верхнее уведомление. Ручное сохранение, сброс и вставка блокируются также на сервере.

Пример браузерной проверки на изолированной записи. Для клиента «QA Alpha» в AL2 виден «Manager One», даже если в исходной строке записано другое значение. При выборе «QA Beta» в AL2 появляется «Manager Two». Выбор «QA Empty» показывает прочерк. Во встроенном браузере проверены значок, подсказка при фокусе, фон, выделение и отсутствие ручного редактора. Запросы прямой записи, сброса и вставки возвращают `403 derived_field`. На рабочем локальном стенде проверен вид AL без сохранения рабочих значений.

## Статусы поручений и ЭТрН

T «Поручения» выбирает один из девяти исходных статусов из справочника «Статусы поручений». U «ЭТрН» выбирает один из семи исходных статусов из справочника «Статусы ЭТрН». Столбцы справочников «Статус» и «Цвет» редактируются общим редактором. Оба редактора рейса используют короткий список. Исходные значения вне справочника сохраняются в исторических рейсах и отображаются до следующего выбора. «Не выбран» и Delete очищают значение.

U2 «Статус ЭТРН» расположен после U и хранит состояние подписания отдельно. В «Статусах подписания ЭТРН» пять стартовых вариантов из исторических значений T. Отсутствие подписи перевозчика или водителя отмечено красной группой, ожидание подписи получателя — жёлтой, подписание водителем или складом и завершение документооборота — зелёной. Для столбца «Цвет» и образцов в списке действует активный пресет. Кнопка быстрого редактирования использует права и интерфейс других справочных полей. Пустой выбор очищает U2. Предыдущие записи T и U сохраняются.

Один раз примените `deploy/etrn_signing_status_column.sql` к целевой БД. Скрипт добавляет U2 в метаданные таблицы, создаёт справочник и фиксирует изменения в аудите одной транзакцией. Повторный запуск сохраняет существующие варианты и их цвета. Номера исходных столбцов в импорте остаются прежними. Личная и системная раскладки, сохранённые до появления U2, получают его после U или перед V, если U в этой раскладке отсутствует.

AN «Срок действия инструкции порожнего» скрыт в исходных настройках «Автовывоза». Его можно включить в настройках видимости с учётом прав. Явные настройки пользователя и суперадминистратора имеют приоритет.

Миграция `deploy/document_status_directories.sql` создаёт справочники из основных списков архивного снимка Google и привязывает их к T и U. Повторный запуск сохраняет пользовательские правки. Во встроенном браузере сверены оба меню, списки из девяти и семи статусов и сохранение после обновления страницы на изолированных данных.

## Очистка ячейки по Delete

Delete на выделенной ячейке таблицы или справочника открывает подтверждение «Очистить ячейку?». Фокус сразу на кнопке «Очистить», Enter подтверждает очистку. Отмена или Esc возвращает фокус на ту же ячейку. Поля только для чтения показывают верхнее синее уведомление. Для обязательных полей проверка справочника сохраняет прежнее значение и сообщает причину. Delete внутри открытого поля ввода удаляет символы по обычным правилам.

Сервер применяет очистку и связанные изменения в одной транзакции. В «Автовывозе» S очищает AM, O очищает P, Q и защищённый снимок R, B очищает AL, K, L и статус заказа, K очищает L, M удаляет реквизиты сдачи из рейса. Очистка S сохраняет строку в выборке. В «Перевозчиках» при очистке идентификатора исчезает оператор ЭДО. В «Автотранспорте» очистка фамилии или имени отвязывает водителя и его данные от машины. Черновик очищается локально и сохраняет свой слот. После подтверждённого сохранения исходная ячейка остаётся выделенной, а очищенные значения получают краткую обводку цветом `--vitrine-preset-red`.

Во встроенном браузере на изолированной базе проверены отмена, защита поля только для чтения, очистка веса, связи S, O, B и M, удаление значения в черновике, очистка оператора по ID и защита обязательного кода. На рабочей локальной базе проверено открытие диалога с отменой.

## Обратная связь для ячеек из справочника

Метка `data-derived-source` включает общий сценарий для ячеек, которые заполняются из справочника. Двойной щелчок, Enter и F2 вызывают верхнее синее уведомление `PlanexNotifications` с тоном `info`: «Данные берутся из справочника. Эту ячейку нельзя редактировать». Ячейку можно выделять и копировать.

Когда отображаемое значение меняется, редактор запускает общую зелёную обводку `vitrine-cell-saved` с цветом `--p-success`. Правило действует для изменения из текущего окна и обновления из другого сеанса. Повтор без изменения значения не запускает анимацию.

Оформление ячейки и анимация находятся в `public/assets/vitrine.css`. Верхнее уведомление реализовано в `public/assets/vitrine-notifications.js`, его оформление находится в `public/assets/vitrine.css`. Общие цвета `--p-info`, `--p-info-fill` и `--p-success` заданы в `public/assets/vitrine.css`.

Пример сверки. В «Автовывозе» дважды щёлкните по AL «Менеджер». На тестовой строке выберите в B другого клиента с другим менеджером и сохраните. В AL видно синее уведомление при двойном щелчке и зелёную обводку при смене значения. Во встроенном браузере проверены локальный клик, собственное обновление, обновление из второго сеанса и сохранение черновика при клике из открытого редактора.

## Связь перевозчика с логистом

«Перевозчики» использует общий редактор справочников. Порядок столбцов — A «Перевозчик», B «ИНН», C «Идентификатор ЭДО», D «Оператор ЭДО», E «Логист». Оператор определяется по трёхсимвольному префиксу ID из справочника «Операторы ЭДО». В нём две колонки, «Код» и «Оператор ЭДО». Код состоит из цифры 2 и двух латинских букв или цифр, регистр приводится к верхнему. Новая запись сохраняется после заполнения обеих ячеек. Код, который используется перевозчиком, защищён от удаления, архивации и замены. Название оператора можно менять. При развёртывании `deploy/edo_operators.sql` создаёт справочник с 17 кодами из [таблицы роуминга ЭДО.МИГ24](https://edo.mig24.ru/roaming). Повторный запуск сохраняет внесённые пользователями изменения. Во встроенном браузере проверены черновик, добавление, подстановка нового кода и запрет удаления связанной записи. При пустом ID или неизвестном префиксе отображается прочерк. Столбец D использует серую заливку активного пресета и доступен для просмотра. При сохранении ID оператор обновляется сразу. Excel принимает идентификатор, а колонку оператора можно опустить. Из снимка Google перенесены 29 идентификаторов, исходный текст столбца G сохранён в реквизитах. Поиск и Excel используют все четыре поля. ИНН хранится текстом. В справочнике сохраняются существующие идентификаторы. Дополнительные реквизиты хранятся в `workspace_meta.carrier_details_<id записи>`.

Локальный импорт читает E:H листа «Справочник» из архивного зеркала Google. `tools/import_carriers_from_snapshot.py` проверяет сопоставление без записи, `--apply` сохраняет изменения в одной локальной транзакции с записью в журнал. Совпадения ищутся по нормализованному названию и сохранённым вариантам написания. Пустые значения снимка сохраняют уже заполненные местные реквизиты. Согласующиеся дубли объединяются, а переносы строк в названии оператора заменяются пробелами.

В локальной версии проверены четыре столбца и 165 записей. На изолированных данных браузер подтвердил редактирование реквизитов, автоподстановку AM при смене S, зелёную обводку после сохранения и блокировку ручного редактирования с серой заливкой активного пресета.

Справочник вида `carriers` привязывается к S в «Вывозе». Модуль `WorkspaceVitrineCatalogLinks.php` использует одну схему для S → AM и B → AL. Назначение хранит ID учётной записи по ID перевозчика в `workspace_meta.catalog_logist_accounts_<id справочника>`. В E и AM отображается ФИО из учётной записи. В E используется общий VitrineSelect с действующими учётными записями логистов и старших логистов. Выбор «Не выбран» снимает назначение. При совпадении ФИО в списке показывается номер учётной записи. Исходные подписи сохранены в `workspace_meta.catalog_logists_<id справочника>` для истории. Если связи с учётной записью нет, E и AM пусты. AM использует общие стили и уведомления ячейки из справочника. Ручные запросы записи или вставки отклоняются с `403 derived_field`.

На изолированной строке проверено отображение логиста по историческому перевозчику, изменение при выборе другого перевозчика, зелёная обводка и прочерк у перевозчика без логиста. На рабочем Windows-стенде проверены варианты S и уведомление AM.

## Справочники с внешним источником

`WorkspaceCatalogs.php` обслуживает каталоги и реквизиты. `workspace-catalogs.js` показывает кнопку ручного обновления только при наличии локального адаптера и прав. Форма передаёт ID справочника, адаптер выбирает диапазон по привязанному источнику. Серверный экземпляр поставляется без Windows-адаптера.

## Пилот отдельной страницы справочника «Клиенты»

Путь `/vitrine?catalog=clients` открывается через «Справочники → Клиенты». Страница использует общий каркас Витрины, шаблон строк, редактор ячеек, настройки отображения, выделение и копирование. В сетке A «Клиент», B «Менеджер», C «Точки выгрузки», D «ИНН» и E «Юридическое название». Поиск учитывает рабочее и юридическое название, ИНН и менеджера. ИНН и юридическое название редактируются в общем однострочном редакторе. ИНН хранится строкой из 10 или 12 цифр с сохранением начальных нулей. Оба реквизита необязательны и сохраняются по ID записи в `workspace_meta.client_requisites_<id>` с обычной ревизией и аудитом. Рабочее имя остаётся основой выбора клиента в рейсе. Импорт Excel со старыми заголовками сохраняет отсутствующие поля реквизитов. Явно пустая ячейка присутствующего столбца очищает соответствующий реквизит. «Активные» и «Архив» показывают соответствующие записи одних и тех же данных.

Название и менеджер редактируются в ячейках. «Добавить клиента» открывает форму с обязательным названием и необязательным менеджером. Кнопка «В архив» относится к выделенной строке и запрашивает подтверждение. Архивную запись можно восстановить. Она исчезает из выбора для новых заявок, а подстановка менеджера для старых строк сохраняется. Переименование хранит прежнее название для исторических ссылок. Локальные назначения менеджера сохраняются при следующем ручном чтении Google.

`WorkspaceClientCatalogGrid.php` адаптирует записи справочника для общей сетки. `WorkspaceCatalogs.php` сохраняет запись, права, ревизию, аудит и событие. `WorkspaceClientManagers.php` объединяет значения источника с локальными назначениями и хранит прежние названия. `vitrine-client-catalog.js` отвечает за кнопки страницы, а `vitrine.css` задаёт только ширины и раскладку справочника поверх общего стиля.

Во встроенном браузере на синтетических данных проверены добавление, ошибка дубликата с черновиком, Tab, сохранение менеджера, поиск, архив и восстановление. Проверено, что AL в «Вывозе» использует новое назначение менеджера даже после переименования и архива клиента. Живая страница открыта в режиме просмотра. Оформление предложено для согласования на первом справочнике.

Во встроенном браузере сверены заголовки и позиции строк 100 и 101 в старой и новой вкладках, редактирование и поиск реквизитов, сохранение начального нуля ИНН и черновика при ошибке. Оба маршрута справочника показывают одинаковые реквизиты.

## Перенос справочника «Клиенты»

Однократный импорт `import_client_directory` доступен суперадминистратору. Модуль `WorkspaceClientTransfer.php` принимает снимок записей, активность, эффективные назначения менеджеров и прежние названия, если они есть. Снимок передают по HTTPS в `POST /api/workspace/catalogs` с обычной сессией и CSRF, его содержимое хранят в приватном окружении. В рабочей копии API используется штатный профиль доступа.

Модуль создаёт каталог и привязку к B в «Вывозе» одной транзакцией. Повтор того же снимка возвращает квитанцию. Если справочник уже есть, его записи и назначения сохраняются. Перенос не входит в автодеплой и не перезаписывает строки «Вывоза». AL подставляется через существующую связь B → AL. Если менеджера нет в источнике, в AL отображается прочерк. На изолированной БД проверены импорт, повтор снимка, отказ от перезаписи, несовпадающий дубль, открытие каталога и подстановка AL при выборе клиентов с разными менеджерами или без назначения.

## Общая модель отображения таблиц

«Вывоз» и пилотный справочник «Клиенты» используют один шаблон Витрины. Источник передаёт столбцы, стабильные идентификаторы строк и начальную страницу до 100 записей. Модуль `vitrine-rows.js` отображает видимый диапазон и подгружает соседние страницы. Адаптер `WorkspaceClientCatalogGrid.php` сохраняет поиск и границы архива при подгрузке. Запрос строк с `clientRequisites=1` получает D и E. Вкладки со старой шапкой продолжают получать прежний набор ячеек до обновления страницы. `vitrine-grid-scope.js` формирует адреса общего API для текущего источника.

Общий блок `.vitrine-grid-region` ограничен шириной родительской области. В режиме «По ширине области» он заполняет родителя. В режиме «Компактно» он занимает до 960 CSS-пикселей. Панель над таблицей занимает всю доступную ширину страницы. Настройка ширины блока действует на область сетки под панелью. Широкие столбцы прокручиваются внутри таблицы. Серый фон закреплённой шапки занимает всю видимую ширину области прокрутки и продолжает фон заголовков справа от последнего столбца. При изменении размеров блока сетка пересчитывает диапазон отрисованных строк.

В «Отображение данных» доступны порядок, видимость и ширина столбцов, цветовые пресеты, контраст линий и ширина блока. `vitrine-display.js` применяет одни и те же правила, а `WorkspaceGridPreferences.php` хранит системные и личные настройки отдельно для каждой таблицы или справочника. В рабочих реестрах и в «Клиентах» область прокрутки по умолчанию занимает всю доступную ширину. Правило действует во всех справочниках. Ширину столбца пользователь меняет перетаскиванием правой границы заголовка, порядок — через «Отображение данных → Порядок столбцов». Общая сетка применяет настройки к заголовкам, данным и черновикам. После перезагрузки настройки восстанавливаются для текущего пользователя и справочника.

Пример сверки на локальном стенде. Откройте «Справочники → Клиенты», затем «Отображение данных → Ширина блока». Переключите режим, обновите страницу и откройте «Вывоз», чтобы сравнить его собственную настройку. Во встроенном браузере на синтетических данных проверены переключение и сохранение режима, перестановка столбцов, клавиатурный переход к строке за пределами первой сотни, подгрузка с поиском и пустой архив. При окне 1280 px компактный блок занял 960 px. При окне 560 px горизонтальная прокрутка осталась внутри блока.

## Учётные записи и роли

«Учётные записи» и «Роли» находятся в меню «Система». В сетке учётных записей есть ФИО, логин, пароль и роль. Логин новых записей и новый логин при смене задаются почтовым адресом длиной до 60 символов. Отдельного поля Email в сетке и Excel нет. Старые короткие логины работают до смены логина. Новая запись создаётся через пустую строку, а архивирование и восстановление доступны в меню строки. Доступные для редактирования архивные записи открываются из фильтра «Архив». Роль выбирается общим VitrineSelect. Сервер проверяет полномочия, допустимые роли и версию записи. При ошибке сохраняются введённые данные и фокус.

Пункт «Учётные записи» выводится в меню «Система» и в навигации журнала только при праве просмотра. Для остальных ролей ссылка отсутствует в разметке. Прямой адрес и прежний маршрут журнала проверяют это же право перед открытием таблицы. Сервер применяет область видимости к списку, поиску, архиву, выгрузке, API и аудиту.

| Роль | Какие записи видит | Что редактирует |
| --- | --- | --- |
| Суперадмин | Все | Все поля с действующей защитой собственной роли и активности |
| Аналитика | Все | Пароли всех записей |
| Админ | Свою, менеджеров и логистов, включая старших | Доступные поля видимых записей с защитой собственной роли и активности |
| Старший менеджер | Свою, обычных менеджеров и диспетчеров | Логины и пароли своей записи и обычных менеджеров |
| Старший логист | Свою, обычных логистов и диспетчеров | Логины и пароли своей записи и обычных логистов |
| Обычный менеджер, логист и другие роли | Раздел недоступен | — |

У ролей с правом создания в активном списке ровно две строки ввода. Суперадмин и аналитика могут назначить любую активную роль, включая собственную. Админ может назначить роль обычного или старшего менеджера либо логиста. Старшие могут назначать обычную и старшую роль своей команды и роль диспетчера. Список роли показывает доступные варианты. Для старших поля учётных записей диспетчеров доступны для просмотра. В меню строки диспетчера доступно удаление с подтверждением и необязательным комментарием. Архивирование, восстановление и импорт учётных записей используют права управления суперадмина и админа. Журнал изменений остаётся доступен без списка сотрудников у ролей, у которых нет доступа к учётным записям.

В ячейке «Пароль» отображается «Скрыт». Если роль может задать новый пароль, справа виден карандаш «Задать новый пароль». Карандаш, двойной щелчок, Enter, F2 или Alt+Enter открывают пустое поле в ячейке. У суперадмина после ввода появляется глаз для показа нового значения. Галочка или Enter сохраняют, крестик или Escape отменяют. Сохранённые пароли хранятся в виде хешей. Сервер возвращает только «Скрыт» и метаданные записи. Аудит содержит признак смены пароля. Для смены своего пароля пользователь повторно входит в приложение. Пароль вводится в редакторе ячейки. Очистка и вставка диапазона в столбец «Пароль» отключены.

Независимая проверка во встроенном браузере охватывает одинарный и двойной щелчки, F2, Tab, Enter, Esc, повторное открытие поля, селект роли и поиск. На изолированной базе проверены границы видимости по ролям в сетке, поиске, архиве, API и журнале, а также смена пароля, вход с новым паролем и запрет правок вне области доступа. Для обеих старших ролей проверены просмотр диспетчеров, выбор роли в новой строке и подтверждение удаления. Серверные проверки на изолированной базе подтвердили создание и удаление диспетчеров и запрет изменения их полей. После удаления столбца Email во встроенном браузере проверены обе пустые строки, редактор логина с клавиатуры, селект роли и режим чтения у диспетчера. На изолированной базе проверены создание и смена логина, вход, отказ при неверном адресе и удаление дублей. [Локальный пример](http://127.0.0.1:33615/vitrine?catalog=employees).

## Статусы

Верхнее меню «Статусы» объединяет «Рейсы», «Клиенты» и статусы полей «Автовывоза». «Рейсы» открывает справочник статусов рейса текущего реестра, а из других справочников — статусы «Автовывоза». В столбце A однострочное название, в B короткий список системных цветов. Изменения используются столбцом A соответствующего реестра. Новые статусы вводятся в нижних строках сетки. «Клиенты» открывает справочник статусов заказа для B. Карточки организаций с менеджерами доступны через «Справочники → Клиенты».

«Поручения», «ЭТрН» и «Подписание ЭТРН» открываются из «Статусов» с учётом прав доступа. «Учётные записи», «Роли» и «Операторы ЭДО» открываются из «Системы». Имя пользователя и назначенные роли находятся у правого края шапки за системным разделителем. Нажатие на имя открывает «Выйти» в том же выпадающем меню, которое используется для разделов шапки. На узком экране навигация прокручивается горизонтально между логотипом и профилем. Состояние подключения объявляется средствами доступности. Фильтр состояния справочника находится в его шапке. Архив строк рабочей таблицы доступен из «Системы».

## Статусы заказов клиентов

«Статусы → Клиенты» открывает справочник статусов заказа с двумя столбцами. В A редактируется однострочное название, в B цвет выбирается коротким списком из системной палитры. По умолчанию предварительный заказ имеет жёлтую заливку, подтверждённый — зелёную. Справочник хранит изменения под стабильными кодами, поэтому название и цвет обновляются и для ранее размеченных заказов. В «Вывозе» редактор B показывает два селекта Витрины и одну кнопку сохранения. Статус относится к строке заказа. Для существующих строк без статуса доступно пустое значение.

В поле «Клиент» варианты фильтруются по введённому фрагменту имени. Подсказку можно выбрать мышью или стрелками и Enter. Tab переводит фокус к статусу. При незавершённом вводе редактор сохраняет черновик и просит выбрать клиента из справочника.

Код статуса хранится в ключе clientOrderStatus рабочего JSON записи. Смена статуса, клиент и производный менеджер сохраняются одной транзакцией. Статус учитывается при проверке версии B и передаётся в событии сохранения. Изменение статуса записывается в журнал операций.

В «Автовывозе» столбцы F «Дата», G «Время», K «Выгрузка» и M «Сдача» используют отдельные списки в меню «Статусы». Списки изначально пусты. Новые статусы добавляются в соответствующем справочнике с выбором группы из системной палитры. Пользователь с правом быстрого редактирования может открыть справочник кнопкой «+» рядом со статусом. У K и M кнопка справа от основного поля открывает справочник точек.

Коды статусов этих полей хранятся в `records.values_json.fieldColorStatuses` по букве столбца. «Без статуса» снимает заливку и сохраняет значение, привязки и реквизиты. Изменение только статуса не проверяет заново исторические дату, время и адрес. При одновременном изменении значения сохраняются обычные правила проверки. Статус участвует в версии ячейки, записывается в журнал и обновляется в других сеансах.

Пример сверки. Откройте B в тестовой строке «Вывоза». Выберите клиента и предварительный статус, перейдите Tab к кнопке и сохраните. Проверьте жёлтый цвет, затем сохраните подтверждённый статус и проверьте зелёный после обновления страницы.

## Стандарт строк справочников

Справочники «Клиенты», «Учётные записи», «Роли», «Статусы клиентов», «Статусы рейса» и отдельные рабочие справочники используют общую сетку. Заголовок имеет вид «Справочник: **Роли**». Жирным выделяется только название справочника. Поиск обновляет строки при вводе без кнопки. Слева от поиска расположен селект Витрины. По умолчанию он показывает «Активные». «Архив» открывает архивные записи, сохраняя запрос. Там, где доступен общий список, есть вариант «Все». Справа от поиска кнопка «Скачать Excel» с иконкой выгружает текущую выборку в `.xlsx`. В файл входят заголовки и сохранённые строки текущего режима и поиска, включая строки за пределами прокрутки. Порядок видимых столбцов сохраняется. Например, в архиве «Точек сдачи» поиск по названию выгружает только подходящие архивные точки. В активных рабочих справочниках рядом с выгрузкой расположена кнопка «Загрузить Excel» той же высоты, что и поиск. В диалоге показывается предупреждение о полной замене. Пользователь выбирает .xlsx, нажимает «Проверить файл» и подтверждает кнопкой «Заменить справочник». Можно загрузить выгрузку справочника со всеми обязательными столбцами. Столбцы «ID записи» и «Версия записи» необязательны и указываются вместе. Один лист формата .xlsx должен содержать заголовки справочника в первой строке и готовые значения без формул. Лимит — 1,9 МБ и 5000 записей. Сервер проверяет всю книгу, показывает количество добавлений, обновлений и архивирований, а затем после подтверждения применяет изменения одной транзакцией. После замены активные записи идут в порядке строк Excel. Отсутствующие в файле записи уходят в архив по штатным правилам. Если архивирование какой-либо записи запрещено, загрузка целиком отклоняется. Для точек выгрузки импорт учитывает закреплённого клиента. Столбец «Контакты» из выгрузки и «Основной контакт» доступны для импорта. Стандарт обязателен для каждого нового справочника. Перевозчики и дополнительные рабочие справочники, подключённые к «Вывозу», открываются из меню «Справочники». Для «Ролей» и «Учётных записей» импорт использует штатные права, проверяет связанность и сохраняет защиту собственной записи. Пароли задаются в ячейке «Пароль». Новая учётная запись из Excel получает случайный секрет и доступна для входа после того, как администратор задаст пароль. На PHP требуются расширения DOM и ZIP.

В активном справочнике с правом добавления внизу три строки ввода. Для «Учётных записей» предусмотрены две строки. Название и другие текстовые поля открываются двойным щелчком или первой набранной клавишей. Цвет и роль выбираются из короткого списка Витрины. Tab перемещает фокус внутри редактора.

После подтверждения части данных справа отображается «Черновик. Не добавлено в справочник». Подтверждение всех обязательных полей автоматически добавляет запись и освобождает строку ввода. Ошибка оставляет данные в черновике и отображается в верхнем уведомлении. Для клиента и перевозчика можно подтвердить пустое назначение менеджера или логиста. Email сотрудника можно дописать после создания. Пароль нового сотрудника вводится в защищённом поле, хранится только в памяти вкладки до отправки и в базе сохраняется только в виде хеша. Пароль действующего сотрудника меняется в карточке.

У сохранённых строк при наведении на номер появляется меню «⋯», доступное также по Shift+F10. «Удалить строку» предлагает подтверждение и архивирует запись. При наличии связей или системном использовании справочник показывает синее уведомление с причиной. Защита проверяется повторно внутри транзакции. Архив сохраняет данные, аудит и идентификаторы. Право управления сохраняется для каждого справочника.

Конфигурация полей описана в `WorkspaceDirectoryGrid.php`. Действия идут через `WorkspaceDirectoryActions.php`, а проверки выполняются на стороне доменных хранилищ. Отдельные справочники используют те же шаблон строк, редактор, виртуальную прокрутку и уведомления.

Пример сверки. В «Статусах клиентов» подтвердите название и проверьте красный черновик. Выберите цвет и проверьте новый статус в B «Вывоза». Откройте меню строки и проверьте верхнее уведомление при попытке удалить статус, назначенный заказу. На изолированной базе во встроенном браузере также проверены создание сотрудника и роли, защита используемого клиента и статуса рейса, архив свободной строки и подстановка логиста в AM из справочника перевозчиков.

Во встроенном браузере сверены заголовки всех основных справочников. На изолированных данных проверены поиск по менеджеру, очистка и пустая выдача, сохранение черновика при фильтрации, а также открытие архива из «Системы».

## Цифровой ввод слота и выделение после сохранения

В C «Слот» допустимы даты от сегодняшней по Москве до 30 календарных дней вперёд включительно. Проверка действует при сохранении, вставке и возврате к исходному значению. При нарушении редактор показывает верхнее уведомление PlanexNotifications, введённые цифры остаются в поле. Ранее сохранённые слоты продолжают отображаться. В изолированном браузере проверены отказ даты 2062 года, верхнее уведомление и сохранение на 30-й день. Вставка проверена на вчера, сегодня, 30-й и 31-й дни и 2062 год.

В колонке с точным названием «Слот» первая цифра открывает стандартный редактор и сразу попадает в поле. В редакторе видны поле и кнопки, адрес ячейки входит в доступное имя диалога. Десять цифр в порядке ЧЧ, ЧЧ и ДДММГГ оформляются как «с 00 до 12 - 25.10.26». Пример ввода **0012251026**. Часы от 00 до 23 и календарная дата проверяются на сервере. Двузначный год относится к диапазону 2000–2099. Ранее сохранённый формат с четырёхзначным годом из этого диапазона сокращается при отображении. Пустая строка очищает слот. Чекбокс «Запросить слот» сохраняет «Слот?» в общей записи. При открытии запроса мышкой поле интервала доступно и получает фокус. Первая принятая цифра или вставка цифр снимает флажок в попапе. Сохранение записывает интервал, отмена оставляет ранее сохранённый запрос. Запрос использует красную заливку текущего цветового пресета и чёрный текст. Шрифт, начертание, размеры и отступы ячейки наследуются от общей сетки. В попапе поле и чекбокс используют общие компоненты Витрины и стандартный отступ группы. Запрос обновляется в открытых сессиях через общий механизм изменений. Сохранение интервала снимает запрос. Старые варианты «слот ?» отображаются тем же способом.

После «Сохранить» или Enter выделение остаётся в редактируемой ячейке. Правило действует в основной сетке, в однопольных редакторах времени, в коротких списках и в справочниках. После автосохранения строки справочника фокус остаётся в освободившейся ячейке ввода.

Во встроенном браузере на тестовых данных проверены первая цифра, отбрасывание букв, форматирование, правка цифр в середине, отказ при неверной дате и сохранение выделения для слота, времени, строки справочника и карточки сотрудника. На рабочем локальном стенде проверено открытие C «Слот» по первой цифре и сохранение выделения при отмене.

Во встроенном браузере проверены компактный попап без видимого заголовка и подсказки, отображение прежнего слота с коротким годом и сохранение нового слота с двумя цифрами года. В рабочем локальном кабинете проверен редактор C «Слот».

Во встроенном браузере проверены запрос из чекбокса, красная заливка при получении сохранённой записи во второй открытой вкладке, отображение старого «слот ?» и снятие запроса при сохранении интервала. В рабочем локальном «Вывозе» проверено открытие запроса мышкой и снятие флажка после первой цифры. В изолированной базе также проверены отмена, вставка интервала и сохранение выделения.

## Минимальная маржа

Справочник «Минимальная маржа» содержит дату начала, минимальный процент от дохода и минимальную сумму в рублях. Дата использует маску поля F. Ввод `021226` отображается как `02.12.26`. Дата уникальна, будущие правила можно добавлять заранее. Процент принимает значения от 0 до 100 с двумя знаками после запятой. Минимальная сумма принимает целые значения от 1 000 до 9 999 999 ₽, отображается с разделителями разрядов и выравнивается вправо. Те же правила действуют в черновике. При изменении Y выбирается последнее активное правило с датой начала не позднее даты рейса в F, включая сам день начала. Если для этой даты правила нет, расход сохраняется по общим правилам. При действующем правиле нужен доход в X и однозначная дата рейса. Сохранённые ранее расходы при добавлении правила не пересчитываются.

Порог равен большему из процентной маржи и фиксированной суммы. Если после нового расхода маржа ниже порога, красная ошибка вверху редактора показывает дату правила и допустимый максимум расхода. Черновик остаётся в поле. Сервер применяет ту же проверку при прямой вставке в таблицу. Успешное сохранение в общем редакторе сопровождается обводкой ячейки без уведомления.

Миграция `deploy/margin_rule_directory.sql` создаёт справочник без тестовых ставок. Во встроенном браузере проверены два тестовых правила, переключение по дате рейса, фиксированный минимум, красная ошибка и отсутствие уведомления об успешном сохранении.

## Комментарий, пробег и суммы

В «Автовывозе» V «Комментарий» использует многострочный редактор без видимого заголовка и подписи о сохранении в БД. W «КМ» принимает целые числа от 1 до 10 000. X «Доход» и Y «Расход» принимают целые суммы от 1 000 до 9 999 999. Для сумм используются пробелы между разрядами и выравнивание вправо в ячейках и редакторе. Числовые редакторы открываются при наборе первой цифры. Диапазоны проверяются сервером при сохранении и вставке в таблицу. Пустое значение допустимо при очистке. Исходные записи сохраняются до редактирования.

Z «Маржа» вычисляется как X − Y в копейках. X, Y и Z используют единый формат с разделением разрядов и показывают два знака после запятой только при наличии копеек. Новые суммы вводятся целыми рублями. При отсутствии или нечисловом значении любого из источников маржа остаётся пустой. Ячейка использует системную серую заливку и доступна только для просмотра. Смена дохода или расхода обновляет маржу в той же транзакции. Пример сверки: 45 000 − 30 998,98 = 14 001,02.

В J «Вес (брутто)» и X «Доход» ввод знака `=` открывает или переключает редактор на арифметическое выражение. Например, `=(30+40)+3*9333` показывает `28 069`. Доступны сложение, вычитание, умножение, деление и скобки. Сервер вычисляет результат без округления и принимает целое число в границах соответствующего поля. Формула сохраняется с ячейкой и видна при повторном открытии. Поиск, маржа, копирование из таблицы и Excel используют результат. Вставка формулы проверяется как обычный ввод. Замена числом и очистка сбрасывают выражение. Отмена вставки восстанавливает сохранённую формулу.

Тот же редактор доступен в J и X новой строки внизу таблицы. Сохранение формулы в такой строке создаёт рейс и записывает результат вместе с выражением.

Во встроенном браузере проверены граничные значения, отказ при выходе за диапазон, формат сумм и заголовок редактора комментариев.

## Однострочный редактор «Релиз»

В колонке «Релиз» используется однострочное поле Витрины. Первая набранная буква или цифра открывает редактор и попадает в поле. Двойной щелчок, Enter и F2 открывают текущее значение. Адрес ячейки остаётся в доступном имени диалога. Попап состоит из поля и стандартных действий. Переносы строк отклоняются при вводе через вставку и при сохранении. После сохранения выделение остаётся в той же ячейке.

Во встроенном браузере проверены открытие «Релиза» первой буквой или цифрой, однострочное поле без растягивания, открытие щелчком с текущим текстом и сохранение без переноса выделения. API сохранения и проверки вставки отклоняют перенос строки.

## Короткий список «Статус» в «Вывозе»

Ячейка A использует тот же компактный попап, что и в локальной Витрине. В попапе видны короткий список, «Сохранить» и «Отмена». Адрес ячейки входит в доступное имя диалога. Видимый заголовок, строка о БД, подсказка по клавишам и «Исходное» скрыты.

### Терминалы постановки

Пункт «Справочники → Терминалы постановки» открывает общий справочник с колонками «Терминал» и «Цвет». В «Вывозе» поле E «Постановка» использует поиск по активным терминалам и сохраняет ссылку на запись. Цвет назначается из системной палитры и служит заливкой E. Существующие терминалы без назначенного цвета отображаются на стандартном фоне. Запись с привязкой к рейсу защищена от удаления, в том числе когда в рабочей базе сохранилось прежнее текстовое значение.

Пример сверки во встроенном браузере. В тестовой таблице найдите терминал по части названия и сохраните его в E. Проверьте цвет и сохранение выделения. Измените цвет в справочнике и повторно откройте «Вывоз». На синтетической базе проверены оба цвета, запрет удаления используемой записи и добавление через черновик с восстановлением трёх пустых строк.

## Цвет ячейки берётся из активного пресета

Справочник хранит цветовую группу из системного списка. Конкретная заливка берётся из активного пресета в «Отображение данных → Цветовые пресеты». Правило распространяется на B «Клиент», E «Постановка», колонки «Цвет» их справочников, черновики и образцы в выпадающих списках. Смена пресета перекрашивает загруженные ячейки и сохраняет исходные назначения цветов. Служебная заливка полей из справочников, в том числе AL «Менеджер» и AM «Логист», берётся из серой группы того же пресета.

Пример сверки во встроенном браузере: на тестовом «Вывозе» назначьте предварительный заказ в B и фиолетовый терминал в E. При переключении с базового на насыщенный пресет B меняется на `#EDE19A`, E — на `#B8AFE0`, AL и AM — на `#C9C9C9`. Проверены все четыре заливки и сохранение исходных цветовых групп.

## Компактный ввод даты и времени в «Вывозе»

В F «Дата» и G «Время» первая цифра открывает общий попап и начинает новое значение. В F ввод `251026` даёт `25.10.26`, двузначный год соответствует 2000–2099. В G ввод `0835` даёт `08:35`. Сохраняется и короткий ввод `835`. Буквы не входят в цифровую маску, дату и время проверяет сервер. Пустое поле очищает ячейку. Tab меняет фокус внутри открытого редактора, Enter сохраняет, Esc отменяет. После сохранения выделение остаётся на исходной ячейке. Прежние значения сохраняются, пока пользователь их явно не изменит.

В F «Дата» таблицы «Автовывоз» сохранение, вставка и восстановление исходного значения принимают даты от 10 календарных дней назад до 60 дней вперёд включительно. Границы считаются от сегодняшней даты по Москве. При выходе за диапазон рабочая таблица показывает ошибку в верхнем уведомлении и оставляет ввод в редакторе.

Пример сверки во встроенном браузере. Введите сегодняшнюю дату в F, нажмите Tab и сохраните. Проверьте, что вчерашняя дата тоже сохраняется, а дата 11 дней назад вызывает верхнее уведомление и остаётся в редакторе. В соседней G введите `2400`, проверьте отказ с сохранением ввода, затем исправьте на `0835`.

## Номер, тип и вес контейнера

- H «Номер КТК» принимает номер грузового контейнера по [ISO 6346](https://www.bic-code.org/identification-number/). Это три латинские буквы владельца, U, шесть цифр серийного номера и контрольная цифра. Латиница приводится к верхнему регистру. Если после трёх букв сразу ввели цифру, поле подставляет обязательную U перед ней. U можно указать и вручную. При вставке пробелы и дефисы-разделители убираются. Контрольная цифра проверяется на сервере.
- I «Тип» связан со справочником «Типы контейнеров» через `catalog_bindings`. Начальные значения `20`, `40` и `45`. Ввод в выделенной ячейке сразу открывает список и фильтрует его. Например, `4` предлагает `40` и `45`. Выбранное значение сохраняется общим редактором. Справочник использует общий стандарт редактирования строк. В локальной базе начальная привязка создаётся идемпотентной командой `python tools/seed_container_types.py` в окружении локального стенда.
- J «Вес» использует цифровую маску общей формы. Ввод `25990` даёт `25 990`. С клавиатуры принимаются цифры, и сервер отклоняет дроби, знаки и единицы измерения. Пробелы между разрядами проставляются автоматически. Сохранение и вставка принимают вес от `1 000` до `50 000` включительно или пустое значение. Значения в столбце выровнены по центру. Старые некорректные значения остаются видимыми до явного изменения.

Во встроенном браузере проверены отказ при ошибочной контрольной цифре и сохранение правильного номера, смена типа через список, нажатия букв и знаков при вводе веса и отображение разрядов у исходного целого значения. На рабочем локальном стенде сверены все три поля без сохранения тестовых данных в рейсы.


## Точки выгрузки и основные контакты

В «Автовывозе» кнопка быстрого редактирования рядом с выбором адреса в K открывает окно «Точки выгрузки: **название клиента**». Клиент определяется по ссылке из B или по однозначному совпадению старого названия со справочником. В окне доступны только точки этого клиента, в том числе при поиске и переключении архива. Для строки без определённого клиента сначала нужно выбрать клиента в B. Общий вход из меню «Справочники» показывает точки всех клиентов.

В «Автовывозе» над списком адресов в столбце K отображается «Выгрузки» и название клиента из B той же строки. Если клиент не указан, заголовок содержит «Выгрузки». В локальном браузере проверены два клиента при открытии мышью и F2.

«Справочники → Точки выгрузки» использует общую таблицу со столбцами «Клиент», «Адрес» и «Контакты». Клиент выбирается из справочника. На каждый адрес клиента создаётся отдельная строка. В «Контактах» виден основной контакт и число дополнительных. Двойной щелчок по ячейке, Enter или F2 открывают список контактов этой точки. В нём можно отредактировать контакты и назначить основной. Для новой строки сначала заполняются клиент и адрес. Удаление точки, использованной в рейсах, блокируется с указанием числа связанных строк.

В «Клиентах» третий столбец «Точки выгрузки» показывает число активных адресов. Двойной щелчок по ячейке открывает попап с общим позиционированием редактора Витрины. Добавление и правка открывают форму с двумя обязательными текстовыми полями «Адрес выгрузки» и «Контакты». «Контакты» — одна строка произвольного текста. Адрес и текст основного контакта сохраняются одной транзакцией. При открытии поля многострочный исходный текст показывается в одну строку, отдельные строки разделяются « · ». Дополнительные контакты редактируются в карточке справочника «Точки выгрузки». После успешного удаления через меню строки попап закрывается и счётчик обновляется. Если удалить точку нельзя, попап остаётся открыт. Используемые в рейсах точки защищены от удаления. При добавлении из окна клиент назначается по ID. У сохранённой точки смена клиента заблокирована в таблице и на сервере. Действие «Точки выгрузки» в меню строки открывает отдельный справочник с фильтром по этому клиенту. В меню точки действие «Открыть клиента» возвращает к записи с тем же ID. Фильтр сохраняется при поиске и чтении строк таблицы. При переименовании клиента адреса и контакты остаются привязанными к той же записи. Удаление клиента с используемыми в справочнике точками запрещено.

В «Вывозе» K «Выгрузка» предлагает адреса выбранного клиента. L «Контакты» доступно для просмотра и показывает основной контакт выбранной точки. Изменение клиента очищает K и L одним сохранением. Исходные K и L сохраняются, пока сотрудник не изменит клиента или точку. Смена основного контакта отражается в связанных рейсах при загрузке строки.

Данные хранятся в `unload_points`, `unload_point_contacts` и `unload_point_origins`. Последняя таблица сохраняет связи с исходными рейсами для проверки использования. Локальная команда `tools/curate_unload_points.py --apply` использует архивный снимок Google от 17 ноября и период по столбцу F с 22 августа по 22 ноября. Она оставила в рабочем справочнике 592 точки. У 472 точек импортировано 586 контактов. Основным назначен наиболее часто встречающийся контакт, при равной частоте — более поздний. Из предварительного импорта 810 записей оставлены в базе для разбора и исключены из выбора. Существующие ручные правки и действующие ссылки имеют приоритет. Проверенные записи переиспользуют прежние идентификаторы. Повторный запуск не меняет данные.

Локальная команда tools/refresh_unload_contact_text.py --apply переносит исходный текст L из самой поздней подходящей строки архивного снимка Google, совпавшей по ID клиента и адресу. Обновлены 476 точек, ещё у 36 текст уже совпадал. У 80 точек подходящий текст в снимке отсутствовал. Команда пропускает неоднозначные совпадения и вручную изменённые точки. Повторный запуск не изменяет записи.

## Учётные записи и назначения клиентов

Источником назначений служат «Система → Учётные записи». Для выбора доступны действующие учётные записи менеджеров и старших менеджеров. ФИО читается из учётной записи, поэтому переименование отражается при следующей загрузке «Клиентов» и AL «Автовывоза». Контактный email назначенного сотрудника виден при наличии доступа к «Учётным записям». Закрытые учётные записи исключены из списка выбора. В попапе клиента двойной щелчок по имени открывает замену, кнопка «Добавить менеджера» добавляет назначение, меню ⋯ позволяет его убрать. Замена сохраняет позицию. В обоих маршрутах «Клиентов» используется один VitrineSelect и общая форма.

Перед переходом создайте таблицу из `deploy/client_account_managers.sql` с правами приложения на чтение и запись. `tools/migrate_client_manager_accounts.php PRIVATE_MAPPING.json` проверяет подготовленные пары `legacyId`, `legacyName`, `accountId`, `accountName` и печатает сводку. Ключ `--apply` переносит назначения одной транзакцией, записывает аудит и включает источник «Учётные записи». Повторный запуск подтверждает выполненный перенос. Исходные связи сохраняются до снятия старого справочника. Если соответствие не установлено, прежнее имя остаётся в строке, а в попапе отмечено «требуется сопоставление» и доступно для замены. Excel использует учётные записи, а старые имена могут совпасть с прежним назначением именно этого клиента.

После включения `client_account_managers_v1` выполните `php tools/rebind_vyvoz_people.php` для предварительного просмотра и повторите с `--apply` для переноса. Команда проходит все строки «Автовывоза», включая архив, сохраняет связи B и S на записи «Клиентов» и «Перевозчиков» и обновляет вычисленные значения AL и AM. Для строк без ссылки используются точное нормализованное название и сохранённые варианты названия. Исходные данные и версии ячеек сохраняются. Неопознанные названия остаются в исходной ячейке и попадают в приватную квитанцию с номерами строк. Запись защищена общей блокировкой изменений. Повторный запуск после переноса показывает ноль изменений, если данные и назначения с тех пор совпадают.

Автоподстановка при чтении, поиске и редактировании использует сохранённый ID организации. Менеджеры и логисты загружаются из связей этих организаций с «Учётными записями». Прежнее имя без учётной записи хранится в `client_account_manager_links.fallback_label`. Числовой `legacy_manager_id` у этой строки служит ключом сохранённого имени. У него нет внешнего ключа на старый каталог. Старый каталог «Сотрудники» снят после переноса в канонической локальной базе. Записи, привязки и таблицы `manager_profiles` и `client_manager_links` удалены. Признак `manager_directory_retired_v1` закрывает старые маршруты и исключает воссоздание таблиц при подготовке схемы. Перед удалением проверено восстановление резервной копии. После удаления на отдельной базе проверены действующий и архивный рейсы, поиск по имени, смена B и S, очистка и возврат исходного значения.

На изолированной базе во встроенном браузере проверены выбор из учётных записей, замена прежнего назначения, порядок, два маршрута «Клиентов» и подстановка в AL «Автовывоза». Серверные проверки подтвердили блокировку закрытых учётных записей, конфликт ревизии и сохранность назначений при импорте Excel.

Историческая запись от 23 ноября. В справочниках «Клиенты» и «Сотрудники» в меню строки было действие «В архив». Из архива запись можно восстановить. Архивирование убирает запись из списков выбора и сохраняет исторические связи. Локальная команда `tools/archive_inactive_client_directory.py --as-of 2026-11-23 --apply` перенесла в архив 277 клиентов и одного менеджера по данным «Вывоза» с 23 августа по 23 ноября. Учтены запланированные рейсы и рабочие строки без даты в этом диапазоне строк. Последняя дата рейса в пределах периода — 19 ноября. В 20 рабочих строках имя клиента не удалось однозначно сопоставить со справочником.

Слева от поиска в «Клиентах» используется VitrineSelect с вариантами «Все клиенты», «Активные» и «Архив». По умолчанию открываются «Активные». Смена фильтра сохраняет поисковую строку, а страницы строк запрашиваются с тем же фильтром. В режиме «Все клиенты» действие меню ⋯ определяется состоянием конкретной записи. Архивные строки доступны для просмотра и восстановления. Пример фильтра сверён с селектом «Категория» на Витрине. Во встроенном браузере проверены все три режима, поиск при смене режима и полный цикл перевода в архив и восстановления на синтетическом клиенте.

Заголовок «Справочник: Клиенты (N)» показывает число сохранённых записей по текущему фильтру и поиску. Счётчик берётся из полного списка строк, включая строки за пределами видимой области, и обновляется вместе с результатами поиска.

До снятия справочника «Сотрудники» использовались тот же селект Витрины и счётчик в заголовке. Слева от поиска есть «Все сотрудники», «Активные» и «Архив». По умолчанию открываются «Активные». Меню ⋯ у архивной строки предлагает восстановление также в режиме «Все сотрудники». Подтверждение показывает имя сотрудника.

Во встроенном браузере проверены все режимы и поиск на локальных данных, а также архивирование и восстановление из общего списка на синтетическом сотруднике.

## Заголовок «Автовывоз»

В меню и заголовке рабочей таблицы используется название «Автовывоз». Старый идентификатор маршрута vyvoz сохранён для существующих ссылок и настроек. Демо-таблицы не выводятся в списке рабочих таблиц. В браузере локальной версии проверены название в меню, жирное начертание «Автовывоз» в заголовке и подписи столбцов веса. Пример для сверки: /vitrine?table=vyvoz.

В общей шапке название размещается слева, фильтры, поиск и действия с файлом — справа в этом порядке. Для фильтров используется VitrineSelect. Выбор значения применяется сразу, поиск обновляет строки по мере ввода. Несколько фильтров и поиск действуют одновременно. В Excel попадают строки из текущего результата. [Локальный пример](http://127.0.0.1:33595/).

## Загрузка и прокрутка «Автовывоза»

Для активного «Автовывоза» сервер выбирает до 6 000 последних подходящих рейсов и сортирует их по дате загрузки F. Внутри даты порядок по умолчанию определяется номером строки. Над каждой группой показывается дата с днём недели, например «14 декабря 2026 года (Понедельник)». Обычные разделители используют фон шапки таблицы. Текущая дата определяется по московскому времени. Её разделитель имеет коричневый фон и белый текст с окончанием « — СЕГОДНЯ». При открытой таблице отметка обновляется при смене даты. Исторические даты, которые нельзя однозначно разобрать, находятся в верхней группе «Дата загрузки не определена». Рейсы с пустой датой относятся к нижней группе «Без даты загрузки». Разделители не входят в навигацию по ячейкам, копирование и Excel.

Подпись даты начинается у первого столбца данных A с тем же отступом, что и текст столбца. Она остаётся видна при горизонтальной прокрутке и использует размер и начертание названия «Автовывоз» в шапке. При открытии таблицы выделение появляется после взаимодействия с сеткой. Для групп статуса после основного поля применяется общий отступ между полями редактора.

После каждой группы с календарной датой доступны две пустые строки для добавления рейсов. Пустая F при первом сохранении наследует дату группы. В F можно указать дату вручную или вставить её вместе с другими полями, соблюдая обычный диапазон дат. Вставка из пустой строки не перезаписывает соседнюю группу. После сохранения фокус переходит на сохранённую ячейку, а новая пустая строка плавно появляется в исходной группе. В архиве и в группах без точной даты эти строки не показываются. Внизу доступны 40 общих строк для ввода.

При изменении F рейс переходит в новую группу без перезагрузки. Прямое редактирование сохраняет фокус на изменённой ячейке и показывает перемещение общей анимацией строки. У коллег перемещение видно, если обе позиции входят в видимую область. Системное снижение движения отключает анимацию.

В таблицах и справочниках открытие редактора ставит курсор в поле без выделения текста. Это относится к формулам, поисковым селектам, старым значениям и форме статуса. Ctrl+A выделяет текст по команде пользователя.

Рейс с распознанной датой можно переместить внутри дня за ручку с шестью точками или стрелками при фокусе на ручке. Порядок общий для всех пользователей. Номер рейса сохраняется, операция записывается в аудит. В сеансах наблюдателей перемещённая видимая строка движется и подсвечивается системным красным фоном по всей ширине с сохранением текущей позиции прокрутки. В режиме уменьшенного движения остаётся подсветка.

Начальные строки загружаются с конца списка виртуальными порциями по 32 строки. Последняя строка центрируется только сразу после входа. Внизу доступны 40 пустых строк ввода. Первое успешное сохранение создаёт рейс и записывает правку в одной транзакции. Фокус переходит сразу на сохранённую ячейку, а таблица сохраняет её положение в окне, когда оно доступно. При ошибке введённый текст остаётся в редакторе. Пустые строки не входят в выгрузку Excel. Отступы для центрирования не входят в число строк и в навигацию. Архив открывается сверху, с более новых строк. При подгрузке по номерам сервер читает только запрошенные рейсы. Списки общих справочников передаются один раз и обновляются по событиям. При прокрутке сетка держит видимые строки с небольшим буфером и заранее запрашивает следующую порцию.

При изменении масштаба кэш удерживает все порции, необходимые текущему окну. Если в окно помещается больше пяти порций, лимит временно увеличивается. Регрессионная проверка воспроизводит прежний сбой, затем подтверждает загрузку большого окна и быстрые разнонаправленные переходы.

В локальном браузере проверены 6 000 строк, переходы Ctrl+Home и Ctrl+End, 45 переходов стрелкой через границу порции, редакторы клиента и перевозчика и архив. При открытии смонтирована 31 строка вместо 58 при той же высоте окна. Сверка одинаковой порции из 100 рейсов подтвердила совпадение значений, вариантов выбора, исходных данных, ревизий и доступности полей. Медианы пяти локальных HTTP-замеров: первое открытие 996 → 827 мс и 7,53 → 1,56 МБ до сжатия, порция из 32 строк 740 → 159 мс. Пример для сверки — /vitrine?table=vyvoz.

## Действия со строкой

Основные таблицы и справочники используют общее меню ⋯ у номера строки. Кнопка видна без наведения. Shift+F10 открывает меню, стрелки переключают пункты, Esc возвращает фокус в ячейку. Дополнительные действия идут первыми, затем архивирование или восстановление, затем удаление. Права доступа и состояние строки определяют доступные пункты.

У «Клиентов» адреса и контакты открываются из C «Точки выгрузки». В рабочей таблице над сеткой слева расположен заголовок «Таблица: **Автовывоз**» по тому же правилу, что и у справочников. Жирным выделяется название таблицы. Справа расположены селект архива и кнопка Excel. В локальной витрине основная таблица отображается как «Автовывоз» в заголовке и в меню. Демо-таблицы исключены из списка рабочих таблиц. Строки в архиве доступны для чтения и восстановления.

Удаление требует подтверждения. Комментарий необязателен и сохраняется в аудите, если его ввели. После сохранения удаляемая строка подсвечивается системным красным и плавно исчезает. В таблице и справочниках список обновляется на месте с сохранением позиции прокрутки. Анимация учитывает системное уменьшение движения. Для справочников сервер проверяет связанные записи перед открытием формы и повторяет проверку при сохранении. Верхнее синее уведомление объясняет запрет. Архивирование и удаление сохраняют исходную запись и историю. Удалённые записи исключаются из всех списков, а причина записывается в журнал изменений. Для рейса версия всей строки проверяется внутри транзакции, чтобы подтверждение относилось к актуальной записи.

После подтверждения удаления рейса «Автовывоз» обновляет только строки сетки, сохраняя текущий поиск, фильтры и положение прокрутки. Видимая строка получает системную красную подсветку и плавно исчезает. При включённом системном снижении движения строка убирается сразу. Если рейс был последним в группе даты, её разделитель исчезает вместе с обновлением списка.

При создании рейса или вставке блока в новые строки открытые таблицы других пользователей однократно подсвечивают каждый видимый новый рейс целиком системным красным цветом. Подсветка не меняет выборку, фокус и прокрутку. Событие передаёт только успешно созданные строки после сохранения.

[Рабочий пример в правилах Витрины](http://127.0.0.1:53418/demo/layout-rules.html#row-actions). Во встроенном браузере проверены архивирование, восстановление, форма причины, запрет удаления используемой записи и запись причины в журнале на синтетических данных. ### Быстрое редактирование справочников

В редакторе селекта «Автовывоза» квадратная кнопка «+» стоит справа от списка и совпадает с ним по высоте. Она доступна старшему менеджеру, старшему логисту, администратору и суперадминистратору при наличии прав на поле и связанный справочник. Кнопка открывает стандартную таблицу справочника в системном диалоге. Для добавления используются пустые строки таблицы, существующие записи открываются двойным щелчком. Активную строку можно перетащить за кнопку с шестью точками рядом с номером. Значок совпадает с ручкой переноса столбцов. Курсор захвата появляется над кнопкой. При фокусе на кнопке строку можно переместить стрелками вверх и вниз. Справочник сохраняет порядок, а при закрытии селект обновляется в том же порядке. Черновик рейса сохраняется. Статус заказа выбирается по коду, поэтому переименование обновляет подпись и сохраняет выбор.

Попап начинается с шапки самого справочника. Встроенная таблица занимает место от верхней границы окна. Доступное имя диалога — «Быстрое редактирование».

Для справочников цветов выгрузки, сдачи, даты и времени загрузки эталон — «Статусы рейса». Общая таблица поддерживает поиск, добавление из черновика, редактирование названия и цвета, перенос, архив и восстановление. Для пустого списка доступны строки добавления. Собственные значения справочника появляются после сохранения, цвет берётся из активного пресета. Перенос в справочнике, открытом из ячейки клиента, применяется внутри его выгрузок и сохраняет позиции других клиентов.

Перенос в быстром справочнике и «Автовывозе», в том числе при смене даты рейса, использует одну анимацию видимой строки на основе `transform` из общего CSS. Движение видно инициатору. У других пользователей перенос рейса сопровождается красным выделением строки. При включённой системной настройке уменьшенного движения сохраняется визуальная обратная связь о внешнем изменении, перемещение происходит сразу.

Сервер проверяет роль, доступ к полю и соответствие справочника как при открытии, так и при обновлении списка. Встраивание разрешено только с того же источника для разрешённого справочника. Остальные страницы сохраняют запрет встраивания.

При изменении контракта полей быстрого редактирования обновляйте версии URL связанных скриптов. После обычного обновления страницы браузер загрузит редактор и компоненты, совместимые с текущими данными.

В браузере на отдельной базе проверены добавление и переименование записи из попапа, обновление списка и сохранение статуса заказа после переименования. Проверки доступа охватили четыре разрешённые роли и обычного менеджера.

В пустых строках для добавления рейса все ячейки используют обычный фон сетки и подсветку выбранной строки. Прочерк и серый фон связанных полей появляются в сохранённых рейсах. Связанные ячейки в строках добавления доступны только для чтения.

В шапке рабочей таблицы «Автовывоз» рядом с состоянием записей расположены статус рейса, клиент, поиск и скачивание Excel. Фильтры применяются сразу и сочетаются с поиском по видимым полям статуса, клиента, номера контейнера и номеру строки. Поиск и выгрузка используют один и тот же список рейсов в окне таблицы. Фильтры формата и оценки предназначены для таблицы примеров.

Кнопка «Копировать» в правой части нижней панели карточки переносит в буфер обмена её доступные заполненные поля обычным текстом. Названия разделов и полей сохраняются. Кнопка доступна после загрузки карточки. После успешного копирования карточка закрывается и сверху появляется зелёное уведомление «Скопировано в буфер обмена». При ошибке карточка остаётся открытой.

Группа документов включает серию и номер паспорта, орган и дату выдачи, дату рождения, серию и номер ВУ, дату его выдачи и срок действия. На сервере и локальном стенде просмотр и редактирование документов работают по общим правам справочников. В текущем режиме разработки эти права одинаковы для всех активных ролей. Настройки учётных записей и справочника ролей подчиняются административным правилам. Документы привязаны к ID водителя. Excel и журнал изменений не включают реквизиты. Журнал фиксирует ID и версию записи. При параллельной правке проверяются текущий водитель и версия документов.

Примените `deploy/fleet_details.sql` после `deploy/fleet_directory.sql`. Для локального наполнения используется `tools/import_fleet_details.py` и архив Google в рабочей БД. Отдельный лист транспорта даёт марки полуприцепов. Связи проверяются по явным парам из подробного списка водителей и рейсов за последние 92 дня. Тягачи с несколькими вариантами полуприцепа остаются без назначения. Документы импортируются по полному ФИО при согласованных номерах в источниках. Дата окончания используется из старого листа «Водители». Правки рабочих записей и журнал сохраняются.

На изолированном стенде во встроенном браузере проверены отдельные поля полуприцепа, сохранение документов и повторное открытие после перезагрузки.

Дата рождения переносится из столбца G листа «Водители справочник» или I листа «Водители» при совпадении полного ФИО и согласованных датах. Серия и номер, орган и дата выдачи извлекаются из архивной строки паспорта. Исходный текст хранится в прежнем поле, а отдельные столбцы редактируются независимо. Примените `deploy/fleet_passport_details.sql` после миграции данных документов. Для локального наполнения используется `tools/import_fleet_passport_details.py`. Во встроенном браузере на изолированном стенде проверены порядок столбцов, сохранение четырёх полей и повторное открытие после перезагрузки.

В «Автовывозе» колонки AL «Менеджер» и AM «Логист» показывают имя и первую букву фамилии с точкой, например «Анна И.». Если у клиента несколько менеджеров, формат применяется к каждому имени. При совпадающих ФИО логистов сохраняется различающий номер учётной записи. Поиск принимает полные и короткие подписи. Excel использует полное значение. Этим же форматом в «Автовывозе» подписываются индикаторы параллельного редактирования и вставки. Справочники и попапы показывают полное ФИО. Одиночное имя и служебная подпись отображаются как записаны.

## Параметры груза в «Автовывозе»

J «Вес (брутто)» и AI «Вес груза (нетто)» используют общий формат веса. Допустимы целые значения от 1 000 до 50 000. Значения веса выровнены по правому краю. AH «Стоимость груза» принимает целое число от 1 000 до 99 999 999. AJ «Места» принимает целое число от 1 до 10 000. Ввод цифры открывает стандартный редактор, числа отображаются с разделением разрядов. AK «Характеристики» принимает свободный текст с переносами строк.

Справочник типов контейнеров управляет цветом I, порогом в килограммах и цветом предупреждения для J. По умолчанию тип 20 использует бирюзовую группу, а предупреждение о весе для типов 20 и 40 — красную группу. Пороги по умолчанию составляют 20 000 и 24 000 кг соответственно. Предупреждение действует начиная с порога, в том числе для результата формулы. Цвета берутся из активного пресета. Справочник доступен через быстрое редактирование из I. Пустой порог отключает предупреждение, пустой цвет оставляет обычную заливку.

Во встроенном браузере на изолированном стенде проверены отклонение стоимости ниже минимума, сохранение верхних границ числовых полей и многострочный текст в AK.

## Закрепление столбцов в общей сетке

В общей сетке кнопка закрепления расположена в каждом заголовке. Столбец перемещается вправо от последнего закреплённого в левой части сетки. Повторное нажатие возвращает его на место в обычном порядке столбцов. Перемещение анимируется, если в настройках устройства разрешено движение. В исходном макете закреплены только номера строк. Закрепление наследует системные настройки и переопределяется пользователем. При скрытии столбца его закрепление восстанавливается вместе с видимостью. Если область слишком узкая, неподвижными остаются первые закреплённые столбцы, которые помещаются с местом для горизонтальной прокрутки.

В заголовках общей сетки ручка с точками позволяет перетащить столбец. Место вставки отмечается вертикальной линией. Стрелки влево и вправо работают с клавиатуры, когда ручка в фокусе. Закреплённые столбцы перемещаются внутри закреплённой группы. Для перестановки и закрепления применяется одна анимация. Кнопка с перечёркнутым глазом скрывает столбец после подтверждения. Вернуть скрытый столбец можно в «Порядке столбцов». Порядок и видимость наследуют системные настройки и переопределяются пользователем.

Граница последнего неподвижного столбца шириной 3 CSS-пикселя проходит через заголовок и строки. Цвет следует настройке «Линии таблицы». Пример для сверки — /vitrine?table=vyvoz. В изолированной сборке проверены закрепление трёх столбцов, работа Enter, положение столбцов после прокрутки, открепление, повторный вход и независимые настройки двух профилей. В Edge дополнительно проверены перестановка мышью и стрелками, анимация перемещения, подтверждение и отмена скрытия, размещение кнопок при минимальной ширине.

Проверка во встроенном браузере. Прокрутить вправо до M, сравнить положение заголовков и ячеек A и B, затем перейти стрелкой из B в C. Закреплённые столбцы остались на месте, а выбранная ячейка C открылась целиком. [Эталон Витрины](http://127.0.0.1:61128/demo/layout-rules.html).

## Цвет статусов поручений и ЭТрН

В справочниках «Статусы поручений» и «Статусы ЭТрН» столбец B «Цвет» принимает системную цветовую группу или пустое значение. Заливка определяется активным пресетом и применяется к выбранным статусам в T и U, включая ранее сохранённые значения, совпадающие со справочником. Excel использует названия цветовых групп. Пустое значение убирает заливку.

В выпадающих списках «Автовывоза» рядом с позициями с назначенной заливкой показан образец из активного пресета. Это правило действует для статуса рейса, статуса заказа, терминала постановки, статуса поручения и статуса ЭТрН. У пунктов без заливки, включая «Не выбран», образец с рамкой заполнен цветом фона списка в текущей теме. Такой же образец используется для пустого пункта в селекторе цвета справочника. Справочные значения для проверки вставки остаются текстовыми.

После `deploy/document_status_directories.sql` примените `deploy/document_status_colors.sql`. В снимке Google у «ЗГ (заявка готова)» устойчивая жёлтая заливка, у «СЭТ ДЛТК» — розовая. Остальные статусы ЭТрН и статусы поручений оставлены без начальной заливки. В источнике они преимущественно без заливки, имеют неоднозначный цвет или отсутствуют. Во встроенном браузере на изолированном стенде проверены выбор цвета в справочнике, отображение в T и U и сохранение заливки после перезагрузки.

## Контрагенты ЭДО

Единый справочник хранит название, ИНН, КПП, ОГРН, ID ЭДО и четыре независимые роли. Оператор ЭДО вычисляется по префиксу ID через справочник «Операторы ЭДО». Фильтр слева от поиска по умолчанию показывает все роли. Поиск и выгрузка Excel учитывают выбранную роль. При загрузке Excel оператор вычисляется заново. ИНН и КПП отличают одноимённые записи в списках выбора.

Во всех четырёх столбцах ролей «Да» использует зелёную группу активного цветового пресета. «Нет» использует обычную заливку таблицы. Во встроенном браузере на изолированном стенде проверены смена заливки после сохранения «Да» и её снятие после сохранения «Нет».

В «Автовывозе» AA, AC, AE и AG предлагают грузоотправителей, заказчиков, грузополучателей и наблюдателей соответственно. AB, AD и AF подставляют оператора и доступны для просмотра. Очистка исходной ячейки очищает оператора в той же операции. Старые значения остаются видны до выбора записи. После выбора сохраняется ссылка на контрагента. У используемой записи нельзя снять роль, на которую ссылаются рейсы, или удалить запись.

Структура и привязки создаются скриптом `deploy/edo_counterparty_directory.sql`. Локальное наполнение использует явные ИНН из AA–AG и распознанные реквизиты из локальных данных рейсов. Во встроенном браузере на изолированном стенде проверены фильтр, список AA, подстановка AB и совместная очистка с сохранением фокуса. [Эталон Витрины](http://127.0.0.1:61128/demo/index.html).

Локальный скрипт `tools/import_edo_counterparties_from_snapshot.py` в папке проекта читает сохранённый снимок Google и дополняет пустые ID ЭДО. Скрипт сопоставляет однозначные реквизиты или точное уникальное название, пропускает конфликтующие ID, сохраняет существующие значения и записывает изменения в журнал. Запуск без `--apply` показывает сводку.

### Поиск и буфер обмена

Поиск в «Автовывозе» учитывает права доступа, исходные значения, отображаемые форматы и связанные справочники. Запрос в формате ячейки находит также числовую Excel-дату и компактно сохранённый слот. В пределах одного запроса сервер повторно использует правила доступа и преобразования одинаковых значений. При длительном запросе в поле виден индикатор, ввод остаётся доступным. При вводе запроса и выборе фильтра выдача начинается под шапкой. Очистка поиска возвращает фокус к нижнему сохранённому рейсу текущей выборки.

Правый клик по полю формы или ячейке открывает меню «Копировать» и «Вставить» в оформлении списка VitrineSelect. В ячейках действуют правила вставки таблицы, в формах — правила текущего поля. Для ячеек только для чтения доступно копирование. Скрытый пароль можно вставить. Исключительно точное совпадение с вариантом позволяет вставить текст в селект без свободного ввода.

Открытое меню удерживает выбранную ячейку и границы выделения. Щелчок за пределами меню закрывает его. `Shift+F10` открывает меню буфера в активной ячейке. Диапазон выделяется перетаскиванием с зажатой левой кнопкой или стрелками с `Shift`. Копирование и вставка через меню или `Ctrl+C` и `Ctrl+V` работают с прямоугольником в видимом порядке строк и столбцов. В буфер записывается текст с табуляцией между столбцами и переносами между строками для обмена с Excel.

При расширении диапазона стрелками таблица подгружает строки по фактическому положению прокрутки. Если исходная строка ушла за пределы окна, `Shift` со стрелками продолжает расширять диапазон от неё.

Выделение использует системный акцент. Скопированный диапазон отмечен голубыми цветами текущей темы `--p-info` и `--p-info-fill`. Рамка толщиной 2 CSS-пикселя по всему периметру проходит через стыки ячеек, сохраняя линии сетки внутри диапазона. На пересечении новое выделение рисуется поверх скопированного. После успешной вставки голубая подсветка снимается. Содержимое буфера можно вставлять повторно.

На время локального тестирования «Автовывоза» при копировании сохранённых ячеек выполняется проверка их текущего формата. Несовместимые значения получают системный красный фон `--p-error-fill`. Подсветка сбрасывается при следующем копировании или успешной вставке. Проверка выполняется без изменений в БД.

Диапазон вставляется одной операцией. Внизу активного «Автовывоза» доступны 40 пустых строк для ввода. Вставку можно начать в любой из них или продолжить в пустые строки из существующих. Заполненные строки блока создают рейсы, полностью пустые строки пропускаются. Проверяются доступ, формат каждой ячейки и зависимости, включая расчёт маржи и адрес выгрузки. При ошибке таблица остаётся в прежнем состоянии. Пустые значения при вставке очищают заполненные ячейки сразу. `Ctrl+Z` возвращает значения, если версии совпадают и связанные поля можно восстановить. Созданные вставкой строки остаются в таблице. В справочниках диапазон вставляется в сохранённые строки.

В «Постановке» вставленный действующий терминал привязывается к справочнику. Старое название можно перенести из другой ячейки «Постановка» при совпадении её значения, ревизии и хэша строки. Такое копирование сохраняет историческое название. Ввод и вставка текста без подтверждённой исходной ячейки используют действующие варианты справочника.

При копировании «Выгрузки» внутри «Автовывоза» контакт переносится автоматически, даже если столбец «Контакты» вне выделения. Действующая точка сохраняет ссылку на справочник и проверяется по клиенту строки назначения. Историческая пара адреса и контакта берётся из проверенной исходной строки. Если производное поле выбрано вместе с исходным, его значение по-прежнему заполняет система.
