# Server copy of DLTK V3 vitrine

PHP-FPM public root: app/local-admin/public. Requests route through public/index.php; Nginx serves assets directly. Only the working DB is used. Runtime config is in a private [workspace] INI file selected by DLTK_CONFIG_FILE. Keep config/runtime.ini, data exports, passwords and backups out of Git. UI components/styles and current keyboard/editing/live-presence behavior are preserved from the local project.

Runtime contract: [workspace] INI, APP_URL/WS_URL/DB_HOST/DB_PORT/DB_NAME/DB_USER/DB_PASSWORD/PRIVATE_DIR. DLTK_CONFIG_FILE selects the private file. APP_URL is a root origin (a separate virtual host/port), not a subdirectory. Preserve the incoming Host header at Nginx. Cookie name is dltk_v3_server and Secure is enabled for HTTPS APP_URL. /api/health returns dltk-v3-server-v1 and checks only the working DB. Unknown legacy source/admin routes return404.

Portable QA: all PHP and JavaScript syntax checks,66 format checks and9 HTTP integration checks passed locally using a dedicated temporary server process. The latter exercised health, distinct cookie, account login,6000-row grid,5 tables/6 roles, configured WebSocket URL, Host/Origin rejection and removed legacy route. No business values were written. Actual Linux deployment/performance remain separate acceptance steps.

## Клиент и менеджер в «Вывозе»

Для включения сценария справочник с `kind='clients'` привязывается к полю B таблицы `vyvoz`. Связь с менеджером хранится в `workspace_meta` под ключом `catalog_managers_<id справочника>` как JSON-объект, где ключи — ID записей справочника, а значения — имена менеджеров. Список использует общий `VitrineSelect`.

Выбранный клиент и вычисленное AL сохраняются в одной транзакции. При чтении AL подставляется из справочника, в том числе для старых строк. Исторические данные при чтении сохраняются. Если клиент или менеджер не указан, значение AL пустое и отображается прочерк. Для AL пишутся отдельные версия, аудит и событие. Ответ сохранения возвращает обновлённую ячейку AL клиенту, который инициировал операцию.

У столбца значок связи с подписью «Из справочника клиентов» при наведении и фокусе. Светлый фон отмечает происхождение значения. AL можно выделять и копировать. Enter и F2 объясняют источник через верхнее уведомление. Ручное сохранение, сброс и вставка блокируются также на сервере.

Пример браузерной проверки на изолированной записи. Для клиента «QA Alpha» в AL2 виден «Manager One», даже если в исходной строке записано другое значение. При выборе «QA Beta» в AL2 появляется «Manager Two». Выбор «QA Empty» показывает прочерк. Во встроенном браузере проверены значок, подсказка при фокусе, фон, выделение и отсутствие ручного редактора. Запросы прямой записи, сброса и вставки возвращают `403 derived_field`. На рабочем локальном стенде проверен вид AL без сохранения рабочих значений.

## Статусы поручений и ЭТрН

T «Поручения» выбирает один из девяти исходных статусов из справочника «Статусы поручений». U «ЭТрН» выбирает один из семи исходных статусов из справочника «Статусы ЭТрН». В справочниках одна колонка «Статус», новые строки добавляются через общий редактор. Оба редактора используют короткий список. Исходные значения вне справочника сохраняются в исторических рейсах и отображаются до следующего выбора. «Не выбран» и Delete очищают значение.

Миграция `deploy/document_status_directories.sql` создаёт справочники из основных списков архивного снимка Google и привязывает их к T и U. Повторный запуск сохраняет пользовательские правки. Во встроенном браузере сверены оба меню, списки из девяти и семи статусов и сохранение после обновления страницы на изолированных данных.

## Очистка ячейки по Delete

Delete на выделенной ячейке таблицы или справочника открывает подтверждение «Очистить ячейку?». Фокус сразу на кнопке «Очистить», Enter подтверждает очистку. Отмена или Esc возвращает фокус на ту же ячейку. Поля только для чтения показывают верхнее синее уведомление. Для обязательных полей проверка справочника сохраняет прежнее значение и сообщает причину. Delete внутри открытого поля ввода удаляет символы по обычным правилам.

Сервер применяет очистку и связанные изменения в одной транзакции. В «Автовывозе» S очищает AM, O очищает P, Q и защищённый снимок R, B очищает AL, K, L и статус заказа, K очищает L, M удаляет реквизиты сдачи из рейса. Очистка S сохраняет строку в выборке. В «Перевозчиках» при очистке идентификатора исчезает оператор ЭДО. В «Автотранспорте» очистка фамилии или имени отвязывает водителя и его данные от машины. Черновик очищается локально и сохраняет свой слот. После подтверждённого сохранения исходная ячейка остаётся выделенной, а очищенные значения получают краткую обводку цветом `--vitrine-preset-red`.

Во встроенном браузере на изолированной базе проверены отмена, защита поля только для чтения, очистка веса, связи S, O, B и M, удаление значения в черновике, очистка оператора по ID и защита обязательного кода. На рабочей локальной базе проверено открытие диалога с отменой.

## Обратная связь для ячеек из справочника

Метка `data-derived-source` включает общий сценарий для ячеек, которые заполняются из справочника. Клик, Enter и F2 вызывают верхнее синее уведомление `PlanexNotifications` с тоном `info`: «Данные берутся из справочника. Эту ячейку нельзя редактировать». Ячейку можно выделять и копировать.

Когда отображаемое значение меняется, редактор запускает общую зелёную обводку `vitrine-cell-saved` с цветом `--p-success`. Правило действует для изменения из текущего окна и обновления из другого сеанса. Повтор без изменения значения не запускает анимацию.

Оформление ячейки и анимация находятся в `public/assets/vitrine-editor.css`. Верхнее уведомление реализовано в `public/assets/vitrine-notifications.js`, его оформление находится в `public/assets/vitrine-base.css`. Общие цвета `--p-info`, `--p-info-fill` и `--p-success` заданы в `public/assets/vitrine/palette.css`.

Пример сверки. В «Вывозе» кликните по AL «Менеджер». На тестовой строке выберите в B другого клиента с другим менеджером и сохраните. В AL видно синее уведомление при клике и зелёную обводку при смене значения. Во встроенном браузере проверены локальный клик, собственное обновление, обновление из второго сеанса и сохранение черновика при клике из открытого редактора.

## Связь перевозчика с логистом

«Перевозчики» использует общий редактор справочников. Порядок столбцов — A «Перевозчик», B «ИНН», C «Идентификатор ЭДО», D «Оператор ЭДО», E «Логист». Оператор определяется по трёхсимвольному префиксу ID из справочника «Операторы ЭДО». В нём две колонки, «Код» и «Оператор ЭДО». Код состоит из цифры 2 и двух латинских букв или цифр, регистр приводится к верхнему. Новая запись сохраняется после заполнения обеих ячеек. Код, который используется перевозчиком, защищён от удаления, архивации и замены. Название оператора можно менять. При развёртывании `deploy/edo_operators.sql` создаёт справочник с 17 кодами из [таблицы роуминга ЭДО.МИГ24](https://edo.mig24.ru/roaming). Повторный запуск сохраняет внесённые пользователями изменения. Во встроенном браузере проверены черновик, добавление, подстановка нового кода и запрет удаления связанной записи. При пустом ID или неизвестном префиксе отображается прочерк. Столбец D использует серую заливку активного пресета и доступен для просмотра. При сохранении ID оператор обновляется сразу. Excel принимает идентификатор, а колонку оператора можно опустить. Из снимка Google перенесены 29 идентификаторов, исходный текст столбца G сохранён в реквизитах. Поиск и Excel используют все четыре поля. ИНН хранится текстом. В справочнике сохраняются существующие идентификаторы. Дополнительные реквизиты хранятся в `workspace_meta.carrier_details_<id записи>`.

Локальный импорт читает E:H листа «Справочник» из архивного зеркала Google. `tools/import_carriers_from_snapshot.py` проверяет сопоставление без записи, `--apply` сохраняет изменения в одной локальной транзакции с записью в журнал. Совпадения ищутся по нормализованному названию и сохранённым вариантам написания. Пустые значения снимка сохраняют уже заполненные местные реквизиты. Согласующиеся дубли объединяются, а переносы строк в названии оператора заменяются пробелами.

В локальной версии проверены четыре столбца и 165 записей. На изолированных данных браузер подтвердил редактирование реквизитов, автоподстановку AM при смене S, зелёную обводку после сохранения и блокировку ручного редактирования с серой заливкой активного пресета.

Справочник вида `carriers` привязывается к S в «Вывозе». Модуль `WorkspaceVitrineCatalogLinks.php` использует одну схему для S → AM и B → AL. Имя логиста хранится по ID перевозчика в `workspace_meta.catalog_logists_<id справочника>`. AM использует общие стили и уведомления ячейки из справочника. Ручные запросы записи или вставки отклоняются с `403 derived_field`.

На изолированной строке проверено отображение логиста по историческому перевозчику, изменение при выборе другого перевозчика, зелёная обводка и прочерк у перевозчика без логиста. На рабочем Windows-стенде проверены варианты S и уведомление AM.

## Справочники с внешним источником

`WorkspaceCatalogs.php` обслуживает каталоги и реквизиты. `workspace-catalogs.js` показывает кнопку ручного обновления только при наличии локального адаптера и прав. Форма передаёт ID справочника, адаптер выбирает диапазон по привязанному источнику. Серверный экземпляр поставляется без Windows-адаптера.

## Пилот отдельной страницы справочника «Клиенты»

Путь `/vitrine?catalog=clients` открывается через «Справочники → Клиенты». Страница использует общий каркас Витрины, шаблон строк, редактор ячеек, настройки отображения, выделение и копирование. В сетке две колонки, «Клиент» и «Менеджер». Поиск выполняется по обеим. «Активные» и «Архив» показывают соответствующие записи одних и тех же данных.

Название и менеджер редактируются в ячейках. «Добавить клиента» открывает форму с обязательным названием и необязательным менеджером. Кнопка «В архив» относится к выделенной строке и запрашивает подтверждение. Архивную запись можно восстановить. Она исчезает из выбора для новых заявок, а подстановка менеджера для старых строк сохраняется. Переименование хранит прежнее название для исторических ссылок. Локальные назначения менеджера сохраняются при следующем ручном чтении Google.

`WorkspaceClientCatalogGrid.php` адаптирует записи справочника для общей сетки. `WorkspaceCatalogs.php` сохраняет запись, права, ревизию, аудит и событие. `WorkspaceClientManagers.php` объединяет значения источника с локальными назначениями и хранит прежние названия. `vitrine-client-catalog.js` отвечает за кнопки страницы, а `vitrine-catalog.css` задаёт только ширины и раскладку справочника поверх общего стиля.

Во встроенном браузере на синтетических данных проверены добавление, ошибка дубликата с черновиком, Tab, сохранение менеджера, поиск, архив и восстановление. Проверено, что AL в «Вывозе» использует новое назначение менеджера даже после переименования и архива клиента. Живая страница открыта в режиме просмотра. Оформление предложено для согласования на первом справочнике.

## Перенос справочника «Клиенты»

Однократный импорт `import_client_directory` доступен суперадминистратору. Модуль `WorkspaceClientTransfer.php` принимает снимок записей, активность, эффективные назначения менеджеров и прежние названия, если они есть. Снимок передают по HTTPS в `POST /api/workspace/catalogs` с обычной сессией и CSRF, его содержимое хранят в приватном окружении. В рабочей копии API используется штатный профиль доступа.

Модуль создаёт каталог и привязку к B в «Вывозе» одной транзакцией. Повтор того же снимка возвращает квитанцию. Если справочник уже есть, его записи и назначения сохраняются. Перенос не входит в автодеплой и не перезаписывает строки «Вывоза». AL подставляется через существующую связь B → AL. Если менеджера нет в источнике, в AL отображается прочерк. На изолированной БД проверены импорт, повтор снимка, отказ от перезаписи, несовпадающий дубль, открытие каталога и подстановка AL при выборе клиентов с разными менеджерами или без назначения.

## Общая модель отображения таблиц

«Вывоз» и пилотный справочник «Клиенты» используют один шаблон Витрины. Источник передаёт столбцы, стабильные идентификаторы строк и начальную страницу до 100 записей. Модуль `vitrine-rows.js` отображает видимый диапазон и подгружает соседние страницы. Адаптер `WorkspaceClientCatalogGrid.php` сохраняет поиск по обеим колонкам и границы архива при подгрузке. `vitrine-grid-scope.js` формирует адреса общего API для текущего источника.

Общий блок `.vitrine-grid-region` ограничен шириной родительской области. В режиме «По ширине области» он заполняет родителя. В режиме «Компактно» он занимает до 960 CSS-пикселей. Панель над таблицей занимает всю доступную ширину страницы. Настройка ширины блока действует на область сетки под панелью. Широкие столбцы прокручиваются внутри таблицы. Серый фон закреплённой шапки занимает всю видимую ширину области прокрутки и продолжает фон заголовков справа от последнего столбца. При изменении размеров блока сетка пересчитывает диапазон отрисованных строк.

В «Отображение данных» доступны порядок, видимость и ширина столбцов, цветовые пресеты, контраст линий и ширина блока. `vitrine-display.js` применяет одни и те же правила, а `WorkspaceGridPreferences.php` хранит личные настройки отдельно для каждой таблицы или справочника. В рабочих реестрах и в «Клиентах» область прокрутки по умолчанию занимает всю доступную ширину. Правило действует во всех справочниках. Ширину столбца пользователь меняет перетаскиванием правой границы заголовка, порядок — через «Отображение данных → Порядок столбцов». Общая сетка применяет настройки к заголовкам, данным и черновикам. После перезагрузки настройки восстанавливаются для текущего пользователя и справочника.

Пример сверки на локальном стенде. Откройте «Справочники → Клиенты», затем «Отображение данных → Ширина блока». Переключите режим, обновите страницу и откройте «Вывоз», чтобы сравнить его собственную настройку. Во встроенном браузере на синтетических данных проверены переключение и сохранение режима, перестановка столбцов, клавиатурный переход к строке за пределами первой сотни, подгрузка с поиском и пустой архив. При окне 1280 px компактный блок занял 960 px. При окне 560 px горизонтальная прокрутка осталась внутри блока.

## Сотрудники и роли

В меню «Справочники» есть три страницы: «Клиенты», «Сотрудники» и «Роли». Все используют общую сетку и личные настройки отображения. «Сотрудники» показывают ФИО, логин, скрытый пароль, email и роль. Учётные записи берутся из `users`, назначения из `user_roles`, email хранится отдельно в `workspace_meta` по ID сотрудника. «Роли» использует стабильные коды из `roles` для списка из пяти системных ролей. Старые назначения сохраняются до явной смены роли.

Карточку добавления и редактирования открывает администратор. Суперадмин назначает административные роли. Роль в карточке и в ячейке выбирается общим VitrineSelect. Tab переводит фокус между полями. Пароль задаётся для новой записи, а пустое поле при редактировании сохраняет действующий пароль. Значения паролей не попадают в сетку, ответы и аудит. Снятие отметки «Учётная запись активна» переводит сотрудника в «Архив». Серверное сохранение и ограничения находятся в `WorkspaceEmployees.php`, чтение страниц сетки — в `WorkspaceDirectoryGrid.php`.

ФИО, логин, email и роль активного сотрудника можно изменить в ячейках общим редактором Витрины. Роль выбирается коротким списком разрешённых назначений. Пароль задаётся в карточке. Сервер сверяет версию всей записи при правке ячейки, затем обновляет её для соседних ячеек. При ошибке редактор сохраняет черновик. Название «Отображение данных» занимает одну строку. Пройден полный цикл на изолированной БД: создание, правка четырёх полей из сетки, проверка конфликта, вход по новому логину, смена пароля в карточке, архив и восстановление. Во встроенном браузере проверены клавиатурный переход Tab, сохранение черновика при неверном email, выбор роли и одна строка в верхнем меню.

Пример сверки. Откройте «Справочники → Роли», затем «Сотрудники». Под администратором выберите строку, откройте карточку и проверьте, что роль выбирается из справочника, а поле нового пароля пустое. Под менеджером доступна сетка для просмотра. Во встроенном браузере проверены переходы между справочниками, выбор роли, Tab и сохранение черновика при дублирующемся логине. На изолированной БД проверены создание и вход сотрудника, смена роли и email, архив и восстановление, права записи и отсутствие паролей в ответах.


## Цвета ячеек

Верхнее меню «Цвета ячеек» объединяет «Статусы» и «Клиенты». «Статусы» открывает справочник статусов рейса текущего реестра, а из других справочников — статусы «Вывоза». В столбце A однострочное название, в B короткий список системных цветов. Изменения используются столбцом A соответствующего реестра. Новые статусы вводятся в нижних строках сетки. «Клиенты» открывает справочник статусов заказа для B. Карточки организаций с менеджерами доступны через «Справочники → Клиенты».

## Статусы заказов клиентов

«Цвета ячеек → Клиенты» открывает справочник статусов заказа с двумя столбцами. В A редактируется однострочное название, в B цвет выбирается коротким списком из системной палитры. По умолчанию предварительный заказ имеет жёлтую заливку, подтверждённый — зелёную. Справочник хранит изменения под стабильными кодами, поэтому название и цвет обновляются и для ранее размеченных заказов. В «Вывозе» редактор B показывает два селекта Витрины и одну кнопку сохранения. Статус относится к строке заказа. Для существующих строк без статуса доступно пустое значение.

В поле «Клиент» варианты фильтруются по введённому фрагменту имени. Подсказку можно выбрать мышью или стрелками и Enter. Tab переводит фокус к статусу. При незавершённом вводе редактор сохраняет черновик и просит выбрать клиента из справочника.

Код статуса хранится в ключе clientOrderStatus рабочего JSON записи. Смена статуса, клиент и производный менеджер сохраняются одной транзакцией. Статус учитывается при проверке версии B и передаётся в событии сохранения. Изменение статуса записывается в журнал операций.

Пример сверки. Откройте B в тестовой строке «Вывоза». Выберите клиента и предварительный статус, перейдите Tab к кнопке и сохраните. Проверьте жёлтый цвет, затем сохраните подтверждённый статус и проверьте зелёный после обновления страницы.

## Стандарт строк справочников

Справочники «Клиенты», «Сотрудники», «Роли», «Статусы клиентов», «Статусы рейса» и отдельные справочники из «Система → Управление справочниками» используют общую сетку. Заголовок имеет вид «Справочник: **Роли**». Жирным выделяется только название справочника. Поиск обновляет строки при вводе без кнопки. Слева от поиска расположен селект Витрины. По умолчанию он показывает «Активные». «Архив» открывает архивные записи, сохраняя запрос. Там, где доступен общий список, есть вариант «Все». Справа от поиска кнопка «Скачать Excel» с иконкой выгружает текущую выборку в `.xlsx`. В файл входят заголовки и сохранённые строки текущего режима и поиска, включая строки за пределами прокрутки. Порядок видимых столбцов сохраняется. Например, в архиве «Точек сдачи» поиск по названию выгружает только подходящие архивные точки. В активных рабочих справочниках рядом с выгрузкой расположена кнопка «Загрузить Excel» той же высоты, что и поиск. В диалоге показывается предупреждение о полной замене. Пользователь выбирает .xlsx, нажимает «Проверить файл» и подтверждает кнопкой «Заменить справочник». Можно загрузить выгрузку справочника со всеми обязательными столбцами. Столбцы «ID записи» и «Версия записи» необязательны и указываются вместе. Один лист формата .xlsx должен содержать заголовки справочника в первой строке и готовые значения без формул. Лимит — 1,9 МБ и 5000 записей. Сервер проверяет всю книгу, показывает количество добавлений, обновлений и архивирований, а затем после подтверждения применяет изменения одной транзакцией. После замены активные записи идут в порядке строк Excel. Отсутствующие в файле записи уходят в архив по штатным правилам. Если архивирование какой-либо записи запрещено, загрузка целиком отклоняется. Для точек выгрузки импорт учитывает закреплённого клиента. Столбец «Контакты» из выгрузки и «Основной контакт» доступны для импорта. Стандарт обязателен для каждого нового справочника. Перевозчики и дополнительные рабочие справочники, подключённые к «Вывозу», открываются из меню «Справочники». Для «Ролей» и «Учётных записей» импорт использует штатные права, проверяет связанность и сохраняет защиту собственной записи. Пароли задаются только в карточке. Новая учётная запись из Excel получает случайный секрет и доступна для входа после того, как администратор задаст пароль. На PHP требуются расширения DOM и ZIP.

В активном справочнике с правом редактирования внизу три строки ввода. Название и другие текстовые поля открываются щелчком или первой набранной клавишей. Цвет и роль выбираются из короткого списка Витрины. Tab перемещает фокус внутри редактора.

После подтверждения части данных справа отображается «Черновик. Не добавлено в справочник». Подтверждение всех обязательных полей автоматически добавляет запись и освобождает строку ввода. Ошибка оставляет данные в черновике и отображается в верхнем уведомлении. Для клиента и перевозчика можно подтвердить пустое назначение менеджера или логиста. Email сотрудника можно дописать после создания. Пароль нового сотрудника вводится в защищённом поле, хранится только в памяти вкладки до отправки и в базе сохраняется только в виде хеша. Пароль действующего сотрудника меняется в карточке.

У сохранённых строк при наведении на номер появляется меню «⋯», доступное также по Shift+F10. «Удалить строку» предлагает подтверждение и архивирует запись. При наличии связей или системном использовании справочник показывает синее уведомление с причиной. Защита проверяется повторно внутри транзакции. Архив сохраняет данные, аудит и идентификаторы. Право управления сохраняется для каждого справочника.

Конфигурация полей описана в `WorkspaceDirectoryGrid.php`. Действия идут через `WorkspaceDirectoryActions.php`, а проверки выполняются на стороне доменных хранилищ. Отдельные справочники используют те же шаблон строк, редактор, виртуальную прокрутку и уведомления.

Пример сверки. В «Статусах клиентов» подтвердите название и проверьте красный черновик. Выберите цвет и проверьте новый статус в B «Вывоза». Откройте меню строки и проверьте верхнее уведомление при попытке удалить статус, назначенный заказу. На изолированной базе во встроенном браузере также проверены создание сотрудника и роли, защита используемого клиента и статуса рейса, архив свободной строки и подстановка логиста в AM из справочника перевозчиков.

Во встроенном браузере сверены заголовки всех основных справочников. На изолированных данных проверены поиск по менеджеру, очистка и пустая выдача, сохранение черновика при фильтрации, а также открытие архива из «Системы».

## Цифровой ввод слота и выделение после сохранения

В колонке с точным названием «Слот» первая цифра открывает стандартный редактор и сразу попадает в поле. В редакторе видны поле и кнопки, адрес ячейки входит в доступное имя диалога. Десять цифр в порядке ЧЧ, ЧЧ и ДДММГГ оформляются как «с 00 до 12 - 25.10.26». Пример ввода **0012251026**. Часы от 00 до 23 и календарная дата проверяются на сервере. Двузначный год относится к диапазону 2000–2099. Ранее сохранённый формат с четырёхзначным годом из этого диапазона сокращается при отображении. Пустая строка очищает слот. Чекбокс «Запросить слот» сохраняет «Слот?» в общей записи. При открытии запроса мышкой поле интервала доступно и получает фокус. Первая принятая цифра или вставка цифр снимает флажок в попапе. Сохранение записывает интервал, отмена оставляет ранее сохранённый запрос. Запрос использует красную заливку текущего цветового пресета и чёрный текст. Шрифт, начертание, размеры и отступы ячейки наследуются от общей сетки. В попапе поле и чекбокс используют общие компоненты Витрины и стандартный отступ группы. Запрос обновляется в открытых сессиях через общий механизм изменений. Сохранение интервала снимает запрос. Старые варианты «слот ?» отображаются тем же способом.

После «Сохранить» или Enter выделение остаётся в редактируемой ячейке. Правило действует в основной сетке, в однопольных редакторах времени, в коротких списках и в справочниках. После автосохранения строки справочника фокус остаётся в освободившейся ячейке ввода.

Во встроенном браузере на тестовых данных проверены первая цифра, отбрасывание букв, форматирование, правка цифр в середине, отказ при неверной дате и сохранение выделения для слота, времени, строки справочника и карточки сотрудника. На рабочем локальном стенде проверено открытие C «Слот» по первой цифре и сохранение выделения при отмене.

Во встроенном браузере проверены компактный попап без видимого заголовка и подсказки, отображение прежнего слота с коротким годом и сохранение нового слота с двумя цифрами года. В рабочем локальном кабинете проверен редактор C «Слот».

Во встроенном браузере проверены запрос из чекбокса, красная заливка при получении сохранённой записи во второй открытой вкладке, отображение старого «слот ?» и снятие запроса при сохранении интервала. В рабочем локальном «Вывозе» проверено открытие запроса мышкой и снятие флажка после первой цифры. В изолированной базе также проверены отмена, вставка интервала и сохранение выделения.

## Комментарий, пробег и суммы

В «Автовывозе» V «Комментарий» использует многострочный редактор без видимого заголовка и подписи о сохранении в БД. W «КМ» принимает целые числа от 1 до 10 000. X «Доход», Y «Расход» и Z «Маржа» принимают целые суммы от 1 000 до 9 999 999. Для сумм используются пробелы между разрядами и выравнивание вправо в ячейках и редакторе. Числовые редакторы открываются при наборе первой цифры. Диапазоны проверяются сервером при сохранении и вставке в таблицу. Пустое значение допустимо при очистке. Исходные записи сохраняются до редактирования.

Во встроенном браузере проверены граничные значения, отказ при выходе за диапазон, формат сумм и заголовок редактора комментариев.

## Однострочный редактор «Релиз»

В колонке «Релиз» используется однострочное поле Витрины. Первая набранная буква или цифра открывает редактор и попадает в поле. Щелчок, Enter и F2 открывают текущее значение. Адрес ячейки остаётся в доступном имени диалога. Попап состоит из поля и стандартных действий. Переносы строк отклоняются при вводе через вставку и при сохранении. После сохранения выделение остаётся в той же ячейке.

Во встроенном браузере проверены открытие «Релиза» первой буквой или цифрой, однострочное поле без растягивания, открытие щелчком с текущим текстом и сохранение без переноса выделения. API сохранения и проверки вставки отклоняют перенос строки.

## Короткий список «Статус» в «Вывозе»

Ячейка A использует тот же компактный попап, что и в локальной Витрине. В попапе видны короткий список, «Сохранить» и «Отмена». Адрес ячейки входит в доступное имя диалога. Видимый заголовок, строка о БД, подсказка по клавишам и «Исходное» скрыты.

### Терминалы постановки

Пункт «Справочники → Терминалы постановки» открывает общий справочник с колонками «Терминал» и «Цвет». В «Вывозе» поле E «Постановка» использует поиск по активным терминалам и сохраняет ссылку на запись. Цвет назначается из системной палитры и служит заливкой E. Существующие терминалы без назначенного цвета отображаются на стандартном фоне. Запись с привязкой к рейсу защищена от удаления, в том числе когда в рабочей базе сохранилось прежнее текстовое значение.

Пример сверки во встроенном браузере. В тестовой таблице найдите терминал по части названия и сохраните его в E. Проверьте цвет и сохранение выделения. Измените цвет в справочнике и повторно откройте «Вывоз». На синтетической базе проверены оба цвета, запрет удаления используемой записи и добавление через черновик с восстановлением трёх пустых строк.

## Цвет ячейки берётся из активного пресета

Справочник хранит цветовую группу из системного списка. Конкретная заливка берётся из активного пресета в «Отображение данных → Цветовые пресеты». Правило распространяется на B «Клиент», E «Постановка», колонки «Цвет» их справочников, черновики и образцы в выпадающих списках. Смена пресета перекрашивает загруженные ячейки и сохраняет исходные назначения цветов. Служебная заливка полей из справочников, в том числе AL «Менеджер» и AM «Логист», берётся из серой группы того же пресета.

Пример сверки во встроенном браузере: на тестовом «Вывозе» назначьте предварительный заказ в B и фиолетовый терминал в E. При переключении с базового на насыщенный пресет B меняется на `#EDE19A`, E — на `#B8AFE0`, AL и AM — на `#C9C9C9`. Проверены все четыре заливки и сохранение исходных цветовых групп.

## Компактный ввод даты и времени в «Вывозе»

В F «Дата» и G «Время» первая цифра открывает общий попап и начинает новое значение. В F ввод `251026` даёт `25.10.26`, двузначный год соответствует 2000–2099. В G ввод `0835` даёт `08:35`. Сохраняется и короткий ввод `835`. Буквы не входят в цифровую маску, дату и время проверяет сервер. Пустое поле очищает ячейку. Tab меняет фокус внутри открытого редактора, Enter сохраняет, Esc отменяет. После сохранения выделение остаётся на исходной ячейке. Прежние значения сохраняются, пока пользователь их явно не изменит.

Пример сверки во встроенном браузере. Выберите F, введите `251026`, нажмите Tab и сохраните. В соседней G введите `2400`, проверьте отказ с сохранением ввода, затем исправьте на `0835`. На изолированном стенде проверены оба сценария и отмена неверной календарной даты.

## Номер, тип и вес контейнера

- H «Номер КТК» принимает номер грузового контейнера по [ISO 6346](https://www.bic-code.org/identification-number/). Это три латинские буквы владельца, U, шесть цифр серийного номера и контрольная цифра. Латиница приводится к верхнему регистру. Если после трёх букв сразу ввели цифру, поле подставляет обязательную U перед ней. U можно указать и вручную. При вставке пробелы и дефисы-разделители убираются. Контрольная цифра проверяется на сервере.
- I «Тип» связан со справочником «Типы контейнеров» через `catalog_bindings`. Начальные значения `20`, `40` и `45`. Ввод в выделенной ячейке сразу открывает список и фильтрует его. Например, `4` предлагает `40` и `45`. Выбранное значение сохраняется общим редактором. Справочник использует общий стандарт редактирования строк. В локальной базе начальная привязка создаётся идемпотентной командой `python tools/seed_container_types.py` в окружении локального стенда.
- J «Вес» использует цифровую маску общей формы. Ввод `25990` даёт `25 990`. С клавиатуры принимаются цифры, и сервер отклоняет дроби, знаки и единицы измерения. Пробелы между разрядами проставляются автоматически. Сохранение и вставка принимают вес от `1 000` до `50 000` включительно или пустое значение. Значения в столбце выровнены по центру. Старые некорректные значения остаются видимыми до явного изменения.

Во встроенном браузере проверены отказ при ошибочной контрольной цифре и сохранение правильного номера, смена типа через список, нажатия букв и знаков при вводе веса и отображение разрядов у исходного целого значения. На рабочем локальном стенде сверены все три поля без сохранения тестовых данных в рейсы.


## Точки выгрузки и основные контакты

«Справочники → Точки выгрузки» использует общую таблицу со столбцами «Клиент», «Адрес» и «Контакты». Клиент выбирается из справочника. На каждый адрес клиента создаётся отдельная строка. В «Контактах» виден основной контакт и число дополнительных. Щелчок по ячейке, Enter или F2 открывают список контактов этой точки. В нём можно отредактировать контакты и назначить основной. Для новой строки сначала заполняются клиент и адрес. Удаление точки, использованной в рейсах, блокируется с указанием числа связанных строк.

В «Клиентах» третий столбец «Точки выгрузки» показывает число активных адресов. Щелчок по ячейке открывает попап у ячейки с общим позиционированием редактора Витрины. Добавление и правка открывают форму с двумя обязательными текстовыми полями «Адрес выгрузки» и «Контакты». «Контакты» — одна строка произвольного текста. Адрес и текст основного контакта сохраняются одной транзакцией. При открытии поля многострочный исходный текст показывается в одну строку, отдельные строки разделяются « · ». Дополнительные контакты редактируются в карточке справочника «Точки выгрузки». После успешного удаления через меню строки попап закрывается и счётчик обновляется. Если удалить точку нельзя, попап остаётся открыт. Используемые в рейсах точки защищены от удаления. При добавлении из окна клиент назначается по ID. У сохранённой точки смена клиента заблокирована в таблице и на сервере. Действие «Точки выгрузки» в меню строки открывает отдельный справочник с фильтром по этому клиенту. В меню точки действие «Открыть клиента» возвращает к записи с тем же ID. Фильтр сохраняется при поиске и чтении строк таблицы. При переименовании клиента адреса и контакты остаются привязанными к той же записи. Удаление клиента с используемыми в справочнике точками запрещено.

В «Вывозе» K «Выгрузка» предлагает адреса выбранного клиента. L «Контакты» доступно для просмотра и показывает основной контакт выбранной точки. Изменение клиента очищает K и L одним сохранением. Исходные K и L сохраняются, пока сотрудник не изменит клиента или точку. Смена основного контакта отражается в связанных рейсах при загрузке строки.

Данные хранятся в `unload_points`, `unload_point_contacts` и `unload_point_origins`. Последняя таблица сохраняет связи с исходными рейсами для проверки использования. Локальная команда `tools/curate_unload_points.py --apply` использует архивный снимок Google от 17 ноября и период по столбцу F с 22 августа по 22 ноября. Она оставила в рабочем справочнике 592 точки. У 472 точек импортировано 586 контактов. Основным назначен наиболее часто встречающийся контакт, при равной частоте — более поздний. Из предварительного импорта 810 записей оставлены в базе для разбора и исключены из выбора. Существующие ручные правки и действующие ссылки имеют приоритет. Проверенные записи переиспользуют прежние идентификаторы. Повторный запуск не меняет данные.

Локальная команда tools/refresh_unload_contact_text.py --apply переносит исходный текст L из самой поздней подходящей строки архивного снимка Google, совпавшей по ID клиента и адресу. Обновлены 476 точек, ещё у 36 текст уже совпадал. У 80 точек подходящий текст в снимке отсутствовал. Команда пропускает неоднозначные совпадения и вручную изменённые точки. Повторный запуск не изменяет записи.

## Сотрудники и назначения клиентов

«Справочники → Сотрудники» использует общую таблицу с полями «Фамилия», «Имя», «Отчество», «Роль», «Телефон» и «Email». Роль выбирается из справочника ролей. Смена имени в карточке менеджера сохраняет все назначения. В ячейке «Менеджер» справочника «Клиенты» и в AL «Менеджер» отображаются имена через запятую. Попап ячейки клиента использует общую таблицу и оформление попапа «Точки выгрузки». Щелчок по имени открывает выбор менеджера, кнопка «Добавить менеджера» добавляет назначение, а меню ⋯ удаляет его из списка клиента. Замена сохраняет позицию назначения. Для выбора используется VitrineSelect. Выбор хранится по ID с сохранением порядка.

Профили хранятся в `manager_profiles`, назначения — в `client_manager_links`. Локальный импорт `tools/import_manager_directory.py` создал 18 менеджеров с ролью «Менеджер» и 436 назначений у 430 клиентов. Поля, которых не было в источнике, оставлены пустыми. Все три назначения у каждого из трёх клиентов сохранены.

Для клиента и менеджера в меню строки есть действие «В архив». Из архива запись можно восстановить. Архивирование убирает запись из списков выбора и сохраняет исторические связи. Локальная команда `tools/archive_inactive_client_directory.py --as-of 2026-11-23 --apply` перенесла в архив 277 клиентов и одного менеджера по данным «Вывоза» с 23 августа по 23 ноября. Учтены запланированные рейсы и рабочие строки без даты в этом диапазоне строк. Последняя дата рейса в пределах периода — 19 ноября. В 20 рабочих строках имя клиента не удалось однозначно сопоставить со справочником.

Слева от поиска в «Клиентах» используется VitrineSelect с вариантами «Все клиенты», «Активные» и «Архив». По умолчанию открываются «Активные». Смена фильтра сохраняет поисковую строку, а страницы строк запрашиваются с тем же фильтром. В режиме «Все клиенты» действие меню ⋯ определяется состоянием конкретной записи. Архивные строки доступны для просмотра и восстановления. Пример фильтра сверён с селектом «Категория» на Витрине. Во встроенном браузере проверены все три режима, поиск при смене режима и полный цикл перевода в архив и восстановления на синтетическом клиенте.

Заголовок «Справочник: Клиенты (N)» показывает число сохранённых записей по текущему фильтру и поиску. Счётчик берётся из полного списка строк, включая строки за пределами видимой области, и обновляется вместе с результатами поиска.

Справочник «Сотрудники» использует тот же селект Витрины и счётчик в заголовке. Слева от поиска есть «Все сотрудники», «Активные» и «Архив». По умолчанию открываются «Активные». Меню ⋯ у архивной строки предлагает восстановление также в режиме «Все сотрудники». Подтверждение показывает имя сотрудника.

Во встроенном браузере проверены все режимы и поиск на локальных данных, а также архивирование и восстановление из общего списка на синтетическом сотруднике.

## Действия со строкой

Основные таблицы и справочники используют общее меню ⋯ у номера строки. Кнопка видна без наведения. Shift+F10 открывает меню, стрелки переключают пункты, Esc возвращает фокус в ячейку. Дополнительные действия идут первыми, затем архивирование или восстановление, затем удаление. Права доступа и состояние строки определяют доступные пункты.

У «Клиентов» адреса и контакты открываются из C «Точки выгрузки». В рабочей таблице над сеткой слева расположен заголовок «Таблица: **Автовывоз**» по тому же правилу, что и у справочников. Жирным выделяется название таблицы. Справа расположены селект архива и кнопка Excel. В локальной витрине основная таблица отображается как «Автовывоз» в заголовке и в меню. Демо-таблицы исключены из списка рабочих таблиц. Строки в архиве доступны для чтения и восстановления.

Удаление требует причины. Для справочников сервер проверяет связанные записи перед открытием формы и повторяет проверку при сохранении. Верхнее синее уведомление объясняет запрет. Архивирование и удаление сохраняют исходную запись и историю. Удалённые записи исключаются из всех списков, а причина записывается в журнал изменений. Для рейса версия всей строки проверяется внутри транзакции, чтобы подтверждение относилось к актуальной записи.

[Рабочий пример в правилах Витрины](http://127.0.0.1:53418/demo/layout-rules.html#row-actions). Во встроенном браузере проверены архивирование, восстановление, форма причины, запрет удаления используемой записи и запись причины в журнале на синтетических данных. В локальном кабинете проверены меню основной таблицы, справочников и доступ к точкам из C.

## Общий цветовой пресет

Выбор в «Отображение данных → Цветовые пресеты» действует для текущего пользователя во всех таблицах и справочниках. Сохранённый выбор в «Вывозе» используется до первого сохранения общего пресета. Ширина, порядок и видимость столбцов сохраняются отдельно для каждой сетки. Цветовая группа в данных остаётся исходной. Оттенок ячейки и образца в селекте вычисляется из общего пресета и обновляется при получении настройки.

## Ширина столбцов

Все таблицы и справочники используют общий регулятор ширины у правой границы заголовка. Ширину можно изменить перетаскиванием или стрелками при фокусе на регуляторе. Суперадмин сохраняет общую ширину по умолчанию для каждой таблицы. Ранее сохранённые ширины активного суперадмина используются до первого изменения общих значений. Если таких учётных записей несколько, используется первая с сохранёнными ширинами по ID.

Личная ширина хранится на сервере для конкретного столбца и действует поверх общей. Двойной щелчок или Home на регуляторе возвращает столбцу ширину по умолчанию, а для суперадмина сбрасывает общее значение до исходной ширины Витрины. Новые общие значения не затрагивают столбцы с сохранённой личной шириной.

## Точки сдачи

В M «Сдача» таблицы «Вывоз» выбирается точка из справочника «Точки сдачи». Поиск начинается с ввода названия. В попапе видны адрес, контакты и постоянная инструкция выбранной точки. Под ними редактируются реквизиты рейса «Релиз сдачи», «Букинг» и «Действует до». Дата вводится по общему шаблону ДД.ММ.ГГ. Tab переводит фокус между полями. Точка и реквизиты сохраняются одной кнопкой.

Точка хранится ссылкой на запись справочника, а реквизиты рейса сохраняются отдельно в данных строки. До выбора точки в M отображается прежний текст. При первом сохранении точки исходный текст остаётся в данных рейса. Попап показывает точку сдачи и её реквизиты. Существующие рейсы при наполнении справочника не обновляются. Справочник поддерживает общий редактор, черновики и меню строки с проверкой использования перед удалением.

Встроенный браузер подтвердил сохранение и повторное открытие точки и реквизитов на тестовом рейсе, редактирование постоянной инструкции и наличие исходного текста в локальном «Вывозе».

В попапах «Менеджеры» и «Точки выгрузки» Enter или F2 открывает ячейку. Стрелки переходят между строками и полями таблицы попапа, Home и End переходят к первой или последней строке. Shift+F10 открывает меню текущей строки. Tab и Shift+Tab перемещают фокус внутри попапа. Enter подтверждает действие, Esc закрывает текущий уровень и возвращает фокус. После сохранения фокус остаётся на отредактированной строке.

В попапе менеджеров показываются ФИО, телефон и Email. «Добавить менеджера» выбирает сотрудника из справочника. «Новый сотрудник» создаёт контактный профиль с ролью «Менеджер» и одновременно назначает его клиенту. Действие «Редактировать сотрудника» в меню строки обновляет общий профиль по его ID и сохраняет роль и назначения. Оба действия требуют права редактирования справочника сотрудников. Стрелка вниз с последней строки переводит фокус к кнопкам списка. Стрелки также работают в меню строки. Если у существующей точки выгрузки контакт отсутствует, её адрес можно исправить отдельно. Для новой точки обязательны адрес и контакты.

Справочник «Сотрудники» содержит контактные профили, раздел «Учётные записи» открывает отдельную таблицу входов. Команда tools/fill_staff_directory.py заполнила для 18 контактных профилей, включая архивный, фамилию и отчество «Неизвестно», телефон +7 916 000 00 00 и Email info@dltk.ru.

## Водители и автотранспорт

В меню справочников открывается «Автотранспорт». В одной строке показаны госномер, марка, тип транспорта, фамилия, имя, отчество и телефон закреплённого водителя. Щелчок или F2 в любом поле водителя открывает общий попап с четырьмя полями. Для назначения обязательны фамилия и имя, а все пустые поля снимают назначение. Совпавшее ФИО использует существующий профиль. Телефон хранится в профиле водителя. Для машины обязателен госномер. Стандартный поиск, черновики и Excel работают по новому набору столбцов.

Настройки, назначения и история используют прежние ID машин и водителей. Профили водителей без назначения доступны для повторной привязки по ФИО.

В O «АМ» таблицы «Автовывоз» машина выбирается из списка с поиском по госномеру и ФИО. В подсказке рядом с номером показан закреплённый водитель. Одно сохранение записывает машину и заполняет P «ФИО» её закреплённым водителем. Если назначения нет, P остаётся пустым. P доступно для просмотра. Назначение в справочнике применяется при следующем сохранении машины в рейсе. Ранее сохранённые рейсы сохраняют указанного в них водителя. Поля телефона и реквизитов рейса ведутся отдельно.

Структура создаётся скриптом `deploy/fleet_directory.sql`. Локальное наполнение выполняет `tools/import_fleet_directory.py` из доступных в БД архивных справочников и недавних рейсов. Автопривязка выполняется только для однозначных пар. Исходные записи рейсов сохраняются, а связи в истории учитываются при проверке удаления.

Во встроенном браузере на изолированном стенде проверены единый пункт меню, редактирование данных водителя, поиск машины по фамилии и автоподстановка ФИО в рейсе.

### Тягачи, полуприцепы и документы

В «Автотранспорте» щелчок или F2 в ячейке открывает один редактор её группы: транспорт, водитель, паспорт или водительское удостоверение. Одна кнопка сохраняет поля группы в одной транзакции. Фокус остаётся на исходной ячейке, Tab переводит фокус между полями, а ошибки оставляют введённые значения в форме. Дата рождения входит в группу водителя при наличии права редактировать документы.

Порядок по умолчанию: марка и госномер тягача, марка и госномер полуприцепа, ФИО, основной и дополнительный телефоны, дата рождения, паспорт и водительское удостоверение. Оба телефона хранятся в профиле водителя. Распознанные российские номера отображаются в формате +7 (XXX) XXX XX XX, белорусские — +375 (XX) XXX XX XX. При неоднозначном значении сохраняется исходный текст. Старый столбец «Тип транспорта» скрыт из таблицы и выгрузки. Прежние значения хранятся в базе. Миграция `deploy/fleet_additional_phone.sql` добавляет поле, а локальный скрипт `tools/import_fleet_additional_phone.py` разделяет однозначные пары номеров. Идентификаторы столбцов и связи с рейсами сохранены. Старый Excel без дополнительного телефона сохраняет уже записанный номер. При первом открытии после смены порядка старые настройки «Автотранспорта» получают согласованную последовательность. Ширины, скрытые столбцы и прочие настройки сохраняются. Последующие перестановки сохраняются по общим правилам. Во всех группах данные относятся к одной строке. В O «АМ» варианты и выбранное значение показывают номера тягача и полуприцепа с фамилией и инициалами. Поиск работает по госномерам и полному ФИО. Редактор O открывается без видимого заголовка и подписи о сохранении в БД. Ячейка O и её выгрузка в Excel показывают госномера и сокращённое ФИО через пробел, например `А123ВС77 / АВ123477 Иванов А.В`. При выборе O фиксирует госномера, P — полное ФИО водителя, а Q — его основной и дополнительный телефоны через запятую. R «ПД» сохраняет паспортные данные, ВУ и дату рождения водителя, если эти данные заполнены. P, Q и R доступны для просмотра, а реквизиты R видит суперадмин с разрешением просмотра справочника водителей. Если водитель не закреплён, поля очищаются. Ранее сохранённые значения меняются при следующем выборе машины. Содержимое R хранится отдельно и не включается в общую выгрузку и события. После сохранения машины реквизиты R приходят сразу в защищённом ответе, а открытые у коллег окна запрашивают только значение R по событию. Журнал записывает факт изменения без реквизитов. Примените `deploy/fleet_trip_documents.sql` перед обновлением кода. Старые адреса справочников транспорта и водителей открывают «Автотранспорт». Исходные записи и ссылки хранятся для истории.

Группа документов включает серию и номер паспорта, орган и дату выдачи, дату рождения, серию и номер ВУ, дату его выдачи и срок действия. Заголовки доступны всем, значения и редактирование доступны суперадмину с правами справочника. Документы привязаны к ID водителя. Excel и журнал изменений не включают реквизиты. Журнал фиксирует ID и версию записи. При параллельной правке проверяются текущий водитель и версия документов.

Примените `deploy/fleet_details.sql` после `deploy/fleet_directory.sql`. Для локального наполнения используется `tools/import_fleet_details.py` и архив Google в рабочей БД. Отдельный лист транспорта даёт марки полуприцепов. Связи проверяются по явным парам из подробного списка водителей и рейсов за последние 92 дня. Тягачи с несколькими вариантами полуприцепа остаются без назначения. Документы импортируются по полному ФИО при согласованных номерах в источниках. Дата окончания используется из старого листа «Водители». Правки рабочих записей и журнал сохраняются.

На изолированном стенде во встроенном браузере проверены отдельные поля полуприцепа, сохранение документов и повторное открытие после перезагрузки.

Дата рождения переносится из столбца G листа «Водители справочник» или I листа «Водители» при совпадении полного ФИО и согласованных датах. Серия и номер, орган и дата выдачи извлекаются из архивной строки паспорта. Исходный текст хранится в прежнем поле, а отдельные столбцы редактируются независимо.
