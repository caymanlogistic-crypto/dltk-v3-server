# Server copy of DLTK V3 vitrine

PHP-FPM public root: app/local-admin/public. Requests route through public/index.php; Nginx serves assets directly. Only the working DB is used. Runtime config is in a private [workspace] INI file selected by DLTK_CONFIG_FILE. Keep config/runtime.ini, data exports, passwords and backups out of Git. UI components/styles and current keyboard/editing/live-presence behavior are preserved from the local project.

Runtime contract: [workspace] INI, APP_URL/WS_URL/DB_HOST/DB_PORT/DB_NAME/DB_USER/DB_PASSWORD/PRIVATE_DIR. DLTK_CONFIG_FILE selects the private file. APP_URL is a root origin (a separate virtual host/port), not a subdirectory. Preserve the incoming Host header at Nginx. Cookie name is dltk_v3_server and Secure is enabled for HTTPS APP_URL. /api/health returns dltk-v3-server-v1 and checks only the working DB. Unknown legacy source/admin routes return404.

Portable QA: all PHP and JavaScript syntax checks,66 format checks and9 HTTP integration checks passed locally using a dedicated temporary server process. The latter exercised health, distinct cookie, account login,6000-row grid,5 tables/6 roles, configured WebSocket URL, Host/Origin rejection and removed legacy route. No business values were written. Actual Linux deployment/performance remain separate acceptance steps.

## Клиент и менеджер в «Вывозе»

Для включения сценария справочник с `kind='clients'` привязывается к полю B таблицы `vyvoz`. Связь с менеджером хранится в `workspace_meta` под ключом `catalog_managers_<id справочника>` как JSON-объект, где ключи — ID записей справочника, а значения — имена менеджеров. Список использует общий `VitrineSelect`.

Выбранный клиент и вычисленное AL сохраняются в одной транзакции. При чтении AL подставляется из справочника, в том числе для старых строк. Исторические данные при чтении сохраняются. Если клиент или менеджер не указан, значение AL пустое и отображается прочерк. Для AL пишутся отдельные версия, аудит и событие. Ответ сохранения возвращает обновлённую ячейку AL клиенту, который инициировал операцию.

У столбца значок связи с подписью «Из справочника клиентов» при наведении и фокусе. Светлый фон отмечает происхождение значения. AL можно выделять и копировать. Enter и F2 объясняют источник через верхнее уведомление. Ручное сохранение, сброс и вставка блокируются также на сервере.

Пример браузерной проверки на изолированной записи. Для клиента «QA Alpha» в AL2 виден «Manager One», даже если в исходной строке записано другое значение. При выборе «QA Beta» в AL2 появляется «Manager Two». Выбор «QA Empty» показывает прочерк. Во встроенном браузере проверены значок, подсказка при фокусе, фон, выделение и отсутствие ручного редактора. Запросы прямой записи, сброса и вставки возвращают `403 derived_field`. На рабочем локальном стенде проверен вид AL без сохранения рабочих значений.

## Обратная связь для ячеек из справочника

Метка `data-derived-source` включает общий сценарий для ячеек, которые заполняются из справочника. Клик, Enter и F2 вызывают верхнее синее уведомление `PlanexNotifications` с тоном `info`: «Данные берутся из справочника. Эту ячейку нельзя редактировать». Ячейку можно выделять и копировать.

Когда отображаемое значение меняется, редактор запускает общую зелёную обводку `vitrine-cell-saved` с цветом `--p-success`. Правило действует для изменения из текущего окна и обновления из другого сеанса. Повтор без изменения значения не запускает анимацию.

Оформление ячейки и анимация находятся в `public/assets/vitrine-editor.css`. Верхнее уведомление реализовано в `public/assets/vitrine-notifications.js`, его оформление находится в `public/assets/vitrine-base.css`. Общие цвета `--p-info`, `--p-info-fill` и `--p-success` заданы в `public/assets/vitrine/palette.css`.

Пример сверки. В «Вывозе» кликните по AL «Менеджер». На тестовой строке выберите в B другого клиента с другим менеджером и сохраните. В AL видно синее уведомление при клике и зелёную обводку при смене значения. Во встроенном браузере проверены локальный клик, собственное обновление, обновление из второго сеанса и сохранение черновика при клике из открытого редактора.

## Связь перевозчика с логистом

Справочник вида `carriers` привязывается к S в «Вывозе». Модуль `WorkspaceVitrineCatalogLinks.php` использует одну схему для S → AM и B → AL. Имя логиста хранится по ID перевозчика в `workspace_meta.catalog_logists_<id справочника>`. AM использует общие стили и уведомления ячейки из справочника. Ручные запросы записи или вставки отклоняются с `403 derived_field`.

На изолированной строке проверено отображение логиста по историческому перевозчику, изменение при выборе другого перевозчика, зелёная обводка и прочерк у перевозчика без логиста. На рабочем Windows-стенде проверены варианты S и уведомление AM.

## Справочники с внешним источником

`WorkspaceCatalogs.php` обслуживает каталоги и реквизиты. `workspace-catalogs.js` показывает кнопку ручного обновления только при наличии локального адаптера и прав. Форма передаёт ID справочника, адаптер выбирает диапазон по привязанному источнику. Серверный экземпляр поставляется без Windows-адаптера.

## Пилот отдельной страницы справочника «Клиенты»

Путь `/vitrine?catalog=clients` открывается через «Справочники → Клиенты». Страница использует общий каркас Витрины, шаблон строк, редактор ячеек, настройки отображения, выделение и копирование. В сетке две колонки, «Клиент» и «Менеджер». Поиск выполняется по обеим. «Активные» и «Архив» показывают соответствующие записи одних и тех же данных.

Название и менеджер редактируются в ячейках. «Добавить клиента» открывает форму с обязательным названием и необязательным менеджером. Кнопка «В архив» относится к выделенной строке и запрашивает подтверждение. Архивную запись можно восстановить. Она исчезает из выбора для новых заявок, а подстановка менеджера для старых строк сохраняется. Переименование хранит прежнее название для исторических ссылок. Локальные назначения менеджера сохраняются при следующем ручном чтении Google.

`WorkspaceClientCatalogGrid.php` адаптирует записи справочника для общей сетки. `WorkspaceCatalogs.php` сохраняет запись, права, ревизию, аудит и событие. `WorkspaceClientManagers.php` объединяет значения источника с локальными назначениями и хранит прежние названия. `vitrine-client-catalog.js` отвечает за кнопки страницы, а `vitrine-catalog.css` задаёт только ширины и раскладку справочника поверх общего стиля.

Во встроенном браузере на синтетических данных проверены добавление, ошибка дубликата с черновиком, Tab, сохранение менеджера, поиск, архив и восстановление. Проверено, что AL в «Вывозе» использует новое назначение менеджера даже после переименования и архива клиента. Живая страница открыта в режиме просмотра. Оформление предложено для согласования на первом справочнике.

## Общая модель отображения таблиц

«Вывоз» и пилотный справочник «Клиенты» используют один шаблон Витрины. Источник передаёт столбцы, стабильные идентификаторы строк и начальную страницу до 100 записей. Модуль `vitrine-rows.js` отображает видимый диапазон и подгружает соседние страницы. Адаптер `WorkspaceClientCatalogGrid.php` сохраняет поиск по обеим колонкам и границы архива при подгрузке. `vitrine-grid-scope.js` формирует адреса общего API для текущего источника.

Общий блок `.vitrine-grid-region` ограничен шириной родительской области. В режиме «По ширине области» он заполняет родителя. В режиме «Компактно» он занимает до 960 CSS-пикселей. Панель над таблицей занимает всю доступную ширину страницы. Настройка ширины блока действует на область сетки под панелью. Широкие столбцы прокручиваются внутри таблицы. Серый фон закреплённой шапки занимает всю видимую ширину области прокрутки и продолжает фон заголовков справа от последнего столбца. При изменении размеров блока сетка пересчитывает диапазон отрисованных строк.

В «Отображение данных» доступны порядок, видимость и ширина столбцов, цветовые пресеты, контраст линий и ширина блока. `vitrine-display.js` применяет одни и те же правила, а `WorkspaceGridPreferences.php` хранит личные настройки отдельно для каждой таблицы или справочника. В рабочих реестрах и в «Клиентах» область прокрутки по умолчанию занимает всю доступную ширину. Ширину столбцов задаёт общая сетка.

Пример сверки на локальном стенде. Откройте «Справочники → Клиенты», затем «Отображение данных → Ширина блока». Переключите режим, обновите страницу и откройте «Вывоз», чтобы сравнить его собственную настройку. Во встроенном браузере на синтетических данных проверены переключение и сохранение режима, перестановка столбцов, клавиатурный переход к строке за пределами первой сотни, подгрузка с поиском и пустой архив. При окне 1280 px компактный блок занял 960 px. При окне 560 px горизонтальная прокрутка осталась внутри блока.

## Сотрудники и роли

В меню «Справочники» есть три страницы: «Клиенты», «Сотрудники» и «Роли». Все используют общую сетку и личные настройки отображения. «Сотрудники» показывают ФИО, логин, скрытый пароль, email и роль. Учётные записи берутся из `users`, назначения из `user_roles`, email хранится отдельно в `workspace_meta` по ID сотрудника. «Роли» использует стабильные коды из `roles` для списка из пяти системных ролей. Старые назначения сохраняются до явной смены роли.

Карточку добавления и редактирования открывает администратор. Суперадмин назначает административные роли. В карточке роль выбирается общим `VitrineSelect`, Tab переводит фокус между полями. Пароль задаётся для новой записи, а пустое поле при редактировании сохраняет действующий пароль. Значения паролей не попадают в сетку, ответы и аудит. Снятие отметки «Учётная запись активна» переводит сотрудника в «Архив». Серверное сохранение и ограничения находятся в `WorkspaceEmployees.php`, чтение страниц сетки — в `WorkspaceDirectoryGrid.php`.

Пример сверки. Откройте «Справочники → Роли», затем «Сотрудники». Под администратором выберите строку, откройте карточку и проверьте, что роль выбирается из справочника, а поле нового пароля пустое. Под менеджером доступна сетка для просмотра. Во встроенном браузере проверены переходы между справочниками, выбор роли, Tab и сохранение черновика при дублирующемся логине. На изолированной БД проверены создание и вход сотрудника, смена роли и email, архив и восстановление, права записи и отсутствие паролей в ответах.
